# claude-kit

**[Как устроен плагин kit — схемы и все развилки →](.claude/docs/work/overview/overview.md)**

Маркетплейс Claude Code с плагином **kit**: каркас работы над проектами (журнал, агенты журнала и git, закрытие шага, хуки правил процесса и `php -l`) и модуль для сайтов на 1С-Битрикс (инициализация проекта, работа на сервере по SSH, а на Битриксе без SSH — через файл `kit-exec.php`, проверки выкладки, снимки публичной части «до/после», скиллы Битрикса). Плагин и документация — на русском; рассчитан на Windows (Git Bash и PowerShell), PhpStorm и OSPanel, но работает и без них.

## Установка

Нужны [Claude Code](https://claude.com/claude-code) и Node.js ≥ 18.

```
claude plugin marketplace add Ozimnadius/claude-kit
claude plugin install kit@claude-kit
```

То же в сессии: `/plugin marketplace add Ozimnadius/claude-kit`, затем `/plugin install kit@claude-kit`. Дальше в папке проекта — `/kit:project-init`.

Из локальной копии репозитория (для разработки): `claude plugin marketplace add <папка репозитория>`.

## Обновление

```
claude plugin marketplace update claude-kit
claude plugin update kit@claude-kit
```

Затем перезапустить сессии Claude Code. При установке плагин копируется в кэш `~/.claude/plugins/cache/claude-kit/kit/<версия>` — Claude Code работает с копией, а не с папкой репозитория; обновление смотрит на версию: без её повышения `claude plugin update` отвечает «already at the latest version».

## Что внутри

| Что | Как вызвать | Зачем |
|---|---|---|
| `/kit:project-init` | командой | новый проект или дополнение существующего: git, `.gitignore`, скан секретов, `.claude/CLAUDE.md` с параметрами, журнал и план выкладки в `.claude/docs`, исключения PhpStorm, `.htaccess`; переезд старой `docs/` в `.claude/docs`; Битрикс — версия PHP прода, проверка снаружи, PhpStorm, скиллы Битрикса в `.claude/skills` и правило пользоваться ими (с 2.7.0) |
| `/kit:step-done` | Claude сам после проверенного шага или командой | журнал и реестр документов (docs-keeper) → при закрытии этапа — документы этапа в `archive/` (с вашего выбора) → один коммит (git-keeper) → проверка → отправка в удалённый репозиторий, если он задан |
| `/kit:deploy-list` | командой или Claude | что залить и что удалить на сервере с последней выкладки |
| `/kit:server` | Claude при необходимости | работа на сервере: сначала SSH (команды оболочки, PHP через `remote-php.js`), иначе на Битриксе файл `kit-exec.php` (Claude открывает его во встроенном браузере, результат видит только вошедший администратор); чтение — сразу, изменения — с согласия |
| `/kit:why` (с 2.11.0) | командой или Claude, когда спрашивают «почему» | почему так сделано — по файлу, функции, строкам или теме: история git (ID шагов) → журнал (шаги, «Решения», баги, сверки) → документы этапов; коротко, у каждого вывода — ссылка на шаг, коммит, решение; только чтение |
| `/kit:report` (с 2.12.0) | командой | отчёт для заказчика текстом в чат: что сделано, что выложено на сайт, что подтвердить, открытые вопросы, что дальше — простыми словами, без хешей, путей и внутренних названий; период — с даты в аргументе, иначе с прошлого отчёта, иначе с начала текущего этапа |
| `/kit:visual` | Claude перед изменением и после или командой | снимки публичной части «до/после» (гость и админ, 1920 и 390), контрольный прогон для замера шума, сравнение пикселей, текста, статусов, JS-ошибок и ответов 4xx/5xx, отчёт `report.html` |
| `kit:docs-keeper` (sonnet) | из `/kit:step-done` | журнал, план выкладки, правила проекта |
| `kit:git-keeper` (haiku) | из `/kit:step-done` | один коммит, проверка путей и секретов, подпись дословно |
| хук SessionStart | сам | раздел «Сейчас» и правила процесса в контекст — при старте, после `/clear` и после сжатия; исключения PhpStorm (`.idea`, `.git`, `.claude`, «Не выкладывать») дописывает в `.idea/deployment.xml` сам (`phpstorm-exclude.js`); сверка с удалённым репозиторием (`remote-check.js`): новые коммиты там — Claude делает `git pull --ff-only`, неотправленные — отправляет, разошлись — стоп |
| хук PostToolUse | сам | `php -l` версией PHP проекта после каждой правки `.php`; ответы на вопросы Claude — во входящие `.claude/kit-inbox.jsonl` для «Решений» (с 2.9.0) |
| хук PreToolUse | сам | запрет `cd` вне подоболочки и `sed -i` по PHP |

Хуки работают только в kit-проектах — там, где есть раздел «Параметры для агентов» в `.claude/CLAUDE.md` или журнал (`.claude/docs/progress.md`, до переезда — `docs/progress.md`). В остальных папках плагин молчит.

## Документы проекта (с 2.3.0)

```
.claude/docs/
  progress.md      журнал: «Сейчас», оглавление этапов, «Документы» (реестр), «Прод: не забыть», текущий этап
  journal/         части журнала (с 2.13.0): decisions.md, bugs.md, reference.md, stages/stage-NN.md — закрытые этапы
  deploy-prod.md   план выкладки
  work/            текущие планы, спеки, чек-листы, материалы задач
  archive/         готовое и устаревшее — туда их переносит /kit:step-done при закрытии этапа
  visual/          снимки /kit:visual — только локально
```

- **Журнал по частям** (с 2.13.0): в `progress.md` — только текущее, остальное — в `journal/`; закрытый этап `/kit:step-done` переносит в `journal/stages/` скриптом `journal-split.js` (строка в строку, с проверкой, что ничего не потерялось). Новые проекты создаются сразу по частям; журнал одним файлом продолжает работать, перевести его предлагает `/kit:project-init` (`journal-split.js --migrate`).
- `.claude` исключается из выкладки целиком: исключения PhpStorm (Excluded Paths) хук дописывает сам при каждом старте сессии — руками в настройки ходить не нужно; для ручной выкладки `.claude` стоит в «Не выкладывать». Так на сервер не уезжают ни журнал, ни планы, ни скриншоты (nginx отдаёт статику мимо `.htaccess`).
- Нужны документы и на сервере (например, открывать их по FTP) — параметр «Документы на сервере: да» (с 2.6.0): автозаливкой уезжают `.claude/docs` (кроме снимков `visual`), `.claude/CLAUDE.md` и `.claude/.htaccess`, всё остальное в `.claude` хук исключает поимённо; нет `.claude/.htaccess` — создаёт («Require all denied»). Если «Exclude items by name» в настройках выкладки PhpStorm отсекает документы (`*.md`, `docs`), хук предупредит — этот список меняете вы. После первой заливки проверьте снаружи, что `/.claude/` закрыта (`check-closed`).
- `.claude` — защищённая папка Claude Code: в режимах Manual и acceptEdits запись туда просит подтверждения (в вопросе есть «разрешить правки в `.claude` на эту сессию»); в auto решает классификатор, в bypassPermissions — без вопросов. Правило allow в settings.json это не снимает.
- Если PhpStorm открыт и новую строку в Excluded Paths не показал — File → Reload All from Disk.
- Проекты со старой `docs/` работают как раньше; переезд — `/kit:project-init` (правит `.gitignore`, переносит файлы по вашей таблице «файл → куда», меняет параметры, записывает старые копии `docs/` на сервере в «Удалить с сервера» — одним шагом и коммитом).

## История: что делали, как проверили, почему так решили (с 2.8.0)

- **«Решения»** в журнале — `№ | Дата | Шаг | Решение | Почему | Что отвергли | Кто`. «Почему» обязательно. Туда же — значимые решения агента (их `/kit:step-done` показывает отдельным списком, чтобы можно было возразить) и изменения правил проекта. Отменённое решение помечается «→ заменено №M».
- **Таблицы этапов** — с колонкой «Как проверено»; тело коммита шага — то же, что в ней.
- Старые журналы не переделываются: старые таблицы остаются как есть, новые записи ложатся рядом в новом формате.
- **Сверка этапа** (с 2.10.0): при закрытии этапа `/kit:step-done` сверяет задуманное (требования спека, задачи плана, иначе — шаги этапа) со сделанным и показывает таблицу; расхождения — одним вопросом: в «Баги на потом», на следующий этап или «не делаем» с причиной в «Решениях». Итог — строка «Сверка …» под таблицей этапа.
- **Чек-лист в планах** (с 2.13.0): в начале плана этапа — строка на задачу (`- [ ] N.M — …`), при закрытии шага `docs-keeper` ставит `[x]` — по плану сразу видно, что сделано.
- **Входящие ответы** (с 2.9.0): хук записывает каждый ваш ответ на вопрос Claude (вопрос, варианты с описаниями, выбор или свой текст) в локальный `.claude/kit-inbox.jsonl` — не в git и не на сервер. `/kit:step-done` берёт оттуда решения для «Решений», пропуская процедурные вопросы вроде «Закрывать шаг?», и после коммита убирает разобранное. Решения не теряются, даже если контекст сессии сжался.

## Superpowers в kit-проекте (с 2.8.0)

Плагин superpowers можно не выключать: kit при старте сессии задаёт правила, как его скиллы работают в kit-проекте.

- Спеки и планы `brainstorming` и `writing-plans` — в `.claude/docs/work/` (`spec-<тема>.md` по шаблону kit с требованиями Т-N и критериями готовности, `plan-<тема>.md`), а не в `docs/superpowers/`.
- Сам superpowers не коммитит: задача плана — шаг kit, коммит — через `/kit:step-done`. Выбранный подход и отвергнутые — в «Решения».
- При автозаливке — без отдельных веток и worktree: правки из них не дойдут до сервера.
- Служебные папки `.superpowers`, `.worktrees`, `docs/superpowers` исключены из выкладки и из git.

## Параметры проекта

Раздел в `.claude/CLAUDE.md` проекта (создаёт `/kit:project-init`):

```markdown
## Параметры для агентов

- Режим: bitrix
- Код пишет: Claude
- Окружение: прод
- Выкладка: PhpStorm Always
- Прод: https://alpha.example.com
- Дев: —
- SSH прод: alpha:/var/www/user100/data/www/alpha.example.com
- SSH дев: —
- PHP на сервере: /opt/php74/bin/php
- PHP: C:\OSPanel\modules\PHP-7.4\php.exe
- Журнал: .claude/docs/progress.md
- План выкладки: .claude/docs/deploy-prod.md
- ID шага: N.M (например 0.3, 2.1)
- Не выкладывать: .idea, .git, .claude
- Документы на сервере: нет
- Не коммитить: bitrix/, upload/ (кроме upload/docs/), *.back*
- Секреты: —
- Удалённый репозиторий: origin
```

- **Выкладка** — `PhpStorm Always` (автозаливка на прод), `вручную; дев — PhpStorm Always` (прод вручную, автозаливка только на дев) или `вручную`.
- **PHP** — абсолютный путь к `php.exe`; относительный путь или другой файл хук `php -l` не принимает и молчит, а файл-канал `kit-exec.js` без него не собирает файл (нужна проверка `php -l`).
- **SSH прод / SSH дев** — `хост:папка сайта`: псевдоним из `~/.ssh/config` (или `user@host`) и абсолютный путь к корню сайта на сервере; `—` — SSH нет: в режиме bitrix при заданном адресе `/kit:server` работает через файл `kit-exec.php`; в общем режиме выполнить на сервере негде — включить SSH. Порт — только через `~/.ssh/config`. Вход — только по ключу без пароля; настройка — `plugins/kit/skills/project-init/reference/ssh.md`.
- **PHP на сервере** — полный путь к PHP CLI нужной версии: команда `php` на хостинге бывает старой (на ispmanager — 5.4).
- **Пути** в «Не выкладывать» и «Не коммитить»: со `/` в любом месте — от корня проекта (`bitrix/` — только корневая папка, копии шаблонов в `local/templates/…/components/bitrix/` коммитятся), без `/` — имя в любом месте пути (`.idea`, `*.back*`).
- **`.claude/worktrees`** — git worktree, которые Claude Code (десктоп) создаёт внутри проекта (полная копия сайта); исключение `.claude` закрывает и их.
- **Служебные папки superpowers** (`.superpowers`, `.worktrees`, `docs/superpowers`) хук исключает из выкладки всегда (с 2.8.0), шаблоны `.gitignore` — из git.
- **Документы на сервере** — `да` или `нет` (по умолчанию): `да` — автозаливка PhpStorm везёт на сервер `.claude/docs`, `.claude/CLAUDE.md` и `.claude/.htaccess`, остальное в `.claude` остаётся исключённым (раздел «Документы проекта»).
- **Удалённый репозиторий** — имя remote в git (`origin`), куда `/kit:step-done` отправляет каждый проверенный коммит (первый раз — после проверки всей истории на секреты); `—` — не отправлять. Адрес хранится в `.git/config`; подключает `/kit:project-init`.

Полное описание ключей — спек `spec-claude-kit.md` (в репозитории — `.claude/docs/work/`), раздел 5.

## Работа с другого компьютера (с 2.5.0)

Если git проекта лежит в закрытом удалённом репозитории (параметр «Удалённый репозиторий»), продолжить работу дома или на другой машине — это:

1. Claude Code, Node.js ≥ 18 и плагин — «Установка» выше (с GitHub).
2. `git clone <адрес>` — для сайтов в ту же папку, что на работе (например `C:\OSPanel\home\<сайт>`); если в параметре «Удалённый репозиторий» не `origin` — `git clone -o <имя> <адрес>`, иначе хук скажет, что такого remote нет. Параметр «PHP» — путь к `php.exe` на машине, и он в git. OSPanel в другой папке — `php -l` молча пропускается, а `kit-exec.php` не собирается.
3. PhpStorm: открыть папку и настроить сервер выкладки (`.idea` не в git); исключения `.idea`, `.git`, `.claude` хук допишет сам при первом старте сессии.
4. SSH к серверу — свой ключ этой машины (`plugins/kit/skills/project-init/reference/ssh.md`); Битрикс без SSH — файл-канал `kit-exec.php`.
5. `/kit:visual` — зависимости ставятся заново; эталоны `before` остались на первой машине — снять заново.
6. Скиллы Битрикса (`.claude/skills`) не в git — `/kit:project-init` поставит их заново (правило проекта напомнит).
7. Работать с одного компьютера за раз: при старте сессии хук сверит ветку с удалённой, и Claude до любой правки подтянет коммиты, сделанные на другой машине (`git pull --ff-only`), а `/kit:step-done` отправит свои. Ветки разошлись — Claude остановится и спросит.

Репозиторий создаёте вы (закрытым и пустым — без README), вход в GitHub/GitLab — тоже вы (окно Git Credential Manager при первой отправке). Секреты в репозиторий не попадают: `.gitignore`, git-keeper и `secret-scan.js`, а перед первой отправкой — проверка всей истории.

## Скиллы Битрикса (с 2.7.0)

В режиме 1С-Битрикс `/kit:project-init` (с вашего согласия) ставит в `.claude/skills` проекта скиллы из открытых репозиториев [bxmaximum/bitrix-framework-skills](https://github.com/bxmaximum/bitrix-framework-skills) — без `bitrix24-*` (они для портала Битрикс24) — и [bitrix-tools/best-practice](https://github.com/bitrix-tools/best-practice): 46 скиллов (ORM, контроллеры, кеш, безопасность, компоненты, инфоблоки, магазин…). В правила проекта (`.claude/CLAUDE.md`, раздел «Код») ложится строка: код на Битриксе — по этим скиллам, начиная с `bitrix-framework`.

- Ставит скрипт `bitrix-skills.js` (`git clone --depth 1` и копирование `skills/<имя>/`), без `npx` и без папки `.agents`. Повторный запуск (`/kit:project-init` → «обновить скиллы Битрикса») заменяет папки скиллов свежими версиями; ваши собственные скиллы в `.claude/skills` не трогаются.
- В git проекта скиллы не попадают (`.gitignore` kit берёт `/.claude/*`): чужие файлы, обновляются раз в месяц. На другом компьютере их ставит `/kit:project-init`.
- На сервер не уезжают: `.claude` исключена из выкладки, а при «Документы на сервере: да» хук исключает `.claude/skills` заранее. `check-closed` их не обходит.
- Описания скиллов попадают в контекст каждой сессии проекта (около 2,5 тысячи токенов). Если сразу после установки Claude их не видит — перезапустить сессию.

## Работа на сервере без SSH (с 2.4.0)

- **Битрикс без SSH — файл `kit-exec.php`.** Claude собирает его из кода задачи (`scripts/kit-exec.js`, проверка `php -l`), кладёт в корень сайта, открывает во встроенном браузере Claude и читает вывод. Файл отдаёт результат только вошедшему администратору (`$USER->IsAdmin()`, остальным — 403), выполняет только вшитый код и только при `?run=<номер запуска>` из своей сборки; вы один раз входите администратором в браузере Claude (пароли вводите вы). При автозаливке PhpStorm файл уезжает сам, иначе его заливаете вы (Upload to…). По окончании работы Claude сам удаляет файл с сервера последним запуском (код `unlink(__FILE__)`, с вашего согласия) и проверяет, что файла там больше нет (404 или страница сайта без строки `KIT-RUN`); вручную (PhpStorm → Remote Host) файл удаляете только если у PHP не хватило прав; в git он не попадает (`/kit-exec.php` в `.gitignore`, в запретах git-keeper и secret-scan).
- **Согласие — как по SSH:** чтение выполняется сразу, любое изменение — только после вопроса в чате с точным кодом. Окна подтверждения в браузере больше нет; Командная PHP-строка через Claude in Chrome (до 2.4.0) удалена.
- **Не Битрикс и без SSH** — выполнить на сервере негде: включите SSH (`plugins/kit/skills/project-init/reference/ssh.md`, «Как включить SSH у хостинга»).
- Общий таймаут SSH (`remote-php.js --timeout`, по умолчанию 90 с), `Include` в `~/.ssh/config`, пути MSYS2 и `DOCUMENT_ROOT` в общем режиме — исправления шагов К13, К14, К16, К20.
- Проекты на Битриксе без SSH после обновления работают сразу, если задан параметр «PHP» (путь к локальному `php.exe`): `/kit:server` сам выберет файл-канал. Но строки «Работа на сервере» в `.claude/CLAUDE.md` и вводная строка раздела «Удалить с сервера» плана выкладки, написанные до 2.4.0, описывают прежний запасной канал: `/kit:server` скажет об этом и предложит заменить их на новый вариант (с вашего согласия). Строку `/kit-exec.php` в `.gitignore` допишет `/kit:project-init` (или Claude при первом запуске) — тоже с согласия.

## Снимки «до/после» (`/kit:visual`, с 2.2.0)

- Нужен установленный Google Chrome (браузеры Playwright не скачиваются) и один раз на машину — зависимости: Claude спросит и выполнит `node visual.js install` — `npm install` playwright-core, pixelmatch, pngjs (~15 МБ) в `%LOCALAPPDATA%\kit\visual\deps`. Обновления плагина их не трогают.
- Список страниц проекта — `.claude/scripts/visual/pages.json` (в git); снимки — `.claude/docs/visual/` (до переезда — `docs/visual/`), **только локально**: инструмент сам кладёт туда `.gitignore` и не снимает, если PhpStorm с автозаливкой Always не исключает папку снимков (снимки из-под админа, nginx отдаёт картинки мимо `.htaccess`); с 2.3.0 исключение дописывает хук.
- Вход администратора — окно Chrome, входите вы сами; сессия хранится в `%LOCALAPPDATA%\kit\visual\auth`, своя на каждый проект.
- В проектах, созданных до 2.2.0: исключения PhpStorm с 2.3.0 дописывает хук; в «Не выкладывать» — `.claude` (или `docs/visual` до переезда).

## Переход с 1.x на 2.0

- Команда `/kit:bitrix-console` переименована в `/kit:server`: сначала SSH, иначе (с 2.4.0) файл `kit-exec.php`; до 2.4.0 — Командная PHP-строка в Chrome. В `docs/deploy-prod.md` и `.claude/CLAUDE.md` проектов заменить `/kit:bitrix-console` на `/kit:server`.
- В проектах добавить параметры `SSH прод`, `SSH дев`, `PHP на сервере`. Проще всего — три строки вручную по образцу из «Параметров проекта» выше (`—`, если SSH нет); или `/kit:project-init` допишет их с согласия (раздел «SSH»). Без них `/kit:server` в режиме bitrix работает через файл `kit-exec.php` (с 2.4.0; до 2.4.0 — через Командную PHP-строку в Chrome).
- После обновления плагина перезапустить сессии Claude Code.

## Перевод проекта со своими агентами на kit

1. `/kit:project-init` в проекте — допишет раздел параметров и недостающие файлы, ничего не перезапишет.
2. Удалить проектные `.claude/agents/docs-keeper.md` и `git-keeper.md`: плагинные агенты называются `kit:docs-keeper` и `kit:git-keeper` и с проектными не пересекаются — останутся два разных агента. Если `.claude/agents/` уезжала на сервер — удалить и там (раздел «Удалить с сервера» плана выкладки).
3. Убрать из `.claude/CLAUDE.md` строки о запуске агентов и о том, что делать, «если агенты не подхватились», — это теперь в плагине.

## Разработка

- Тесты: `npm ci` один раз (devDependencies `pngjs` и `pixelmatch` — для тестов сравнения снимков), затем `npm test` (`node --test tests/*.test.js`); PHP-тесты используют `C:\OSPanel\modules\PHP-7.2`, `PHP-7.4`, `PHP-8.3` и пропускаются, если их нет.
- Проверка манифестов: `claude plugin validate plugins/kit --strict` и `claude plugin validate . --strict`.
- Запуск без установки: `claude --plugin-dir <папка репозитория>\plugins\kit` (читает папку напрямую).
- Защита от утечек: `node tools/kit-denylist.js install` ставит хуки git, которые не пропустят в коммит (файлы и сообщение) слова из вашего локального списка `.git/info/kit-denylist` — имена клиентов, домены, учётки; список в репозиторий не попадает. `node tools/kit-denylist.js tree` — проверить все файлы.
- Выпуск: поднять `version` в `plugins/kit/.claude-plugin/plugin.json` и в записи плагина в `.claude-plugin/marketplace.json` (одинаково; тест `tests/manifest.test.js` это проверяет) — без новой версии `claude plugin update` изменений не увидит.
- Обзор со схемами — `.claude/docs/work/overview/` (`overview.md` для GitHub, `overview.html` для браузера, схемы в `img/`); собирается из `build/` командой `node .claude/docs/work/overview/build/build.js` — правки вносить туда, а не в собранные файлы.
- Журнал разработки — `.claude/docs/progress.md`, спек — `.claude/docs/work/spec-claude-kit.md`, планы завершённых этапов — `.claude/docs/archive/` (реестр — раздел «Документы» журнала). Проекты, на которых проверялся плагин, в документах обезличены: alpha, beta, gamma…, домены `*.example.com`.
- Снимки вживую (Chrome и сайт) тестами не проверяются: `node plugins/kit/scripts/visual.js …` из корня проекта; `KIT_VISUAL_HOME` — другая папка на машине вместо `%LOCALAPPDATA%\kit\visual`, `KIT_VISUAL_DEPS` — папка с `node_modules` (так тесты берут зависимости из корня репозитория).
