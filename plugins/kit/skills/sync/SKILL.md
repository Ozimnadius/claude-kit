# Синхронизация с продом

Скрипт сверяет сайт на сервере с git, забирает изменения «без kit» в рабочую копию и сам делает коммит синхронизации. Твоя работа — запустить его и по коду выхода сказать пользователю итог или задать вопрос. Коммит делает скрипт: `/kit:step-done` не нужен.

## Когда

- Только по просьбе пользователя: `/kit:sync` или «синхронизируй с продом». Сам не запускай: ни при старте сессии, ни перед выкладкой, ни «заодно».
- Только в kit-проекте, где задан адрес сервера окружения («Прод» / «Дев») или «SSH прод» / «SSH дев» в `.claude/CLAUDE.md`. Иначе скрипт ответит кодом 2 — синхронизировать не с чем.
- Исполнитель Мэтта синхронизацию не запускает. В worktree скрипт только сверяет основную папку — передай его строку пользователю и ничего не делай.

## Запуск

Bash из корня проекта, без `cd`, с параметром `timeout` 300000:

```
node "${CLAUDE_PLUGIN_ROOT}/scripts/prod-sync.js" [--check]
```

`--check` — только посмотреть, что синхронизация заберёт: ничего не пишется. Других аргументов не добавляй, кроме флагов ответа ниже и `--timeout 250` при «вышло время».

## По коду выхода

Последняя строка вывода — итог для пользователя (код 0) или что делать тебе. Строки выше — подробности: покажи их, если пользователь спросит или они нужны для вопроса (при коде 0 — см. таблицу).

| Код | Значение | Что делать |
|---|---|---|
| 0 | синхронизация сделана или нечего забирать | передай последнюю строку и строки перед ней, кроме «Сервер:», «База:», «Сверка —» («коммит синхронизации не отправлен…», «Повтор после остановки…» и др.); есть «Совмещено…» — покажи панель изменений |
| 1 | нужен ответ пользователя | раздел «Вопрос пользователю» |
| 2 | синхронизировать не с чем, параметр неверный, нет папки сайта на сервере | есть «спроси пользователя» — как при коде 1; иначе скажи последнюю строку, неверный параметр — предложи `/kit:project-init` |
| 3 | нет подключения, обрыв, вышло время | «Повторить» / «Отложить»; при «вышло время» повтор — с `--timeout 250` (Bash `timeout` тот же) |
| 4 | аргументы, git или отметка не записана | покажи вывод и остановись; в выводе «повтор … безопасен» — спроси «Повторить» / «Отложить» |

## Вопрос пользователю

В последней строке есть «спроси пользователя» (бывает «спроси пользователя:», «…по каждому:», «…одним AskUserQuestion:»). После него — варианты через « / »; вопросов может быть два, они через «; ».

1. Задай один AskUserQuestion; варианты — кнопки в порядке скрипта (рекомендуемый скрипт выделяет — ставь первым). `multiSelect: false`.
2. Вариант с командой в обратных кавычках: ответ — запуск скрипта с этими флагами (`--watchers-ok`, `--big-ok`, `--delete-ok`, `--ftp-done`, `--dirty-ok`, `--abort`), `timeout` 300000. Два вопроса (File Watchers и объём), оба ответа «забирать» — флаги в одном запуске: `--watchers-ok --big-ok`.
3. «Повторить» без команды — тот же запуск с теми же флагами, что дали остановку (включая уже переданные флаги ответа и `--ftp-done`): голый запуск снова остановится на том же вопросе.
4. «Отложить», «Не буду скачивать», «Оставить нашу» — остановись и коротко скажи, что ничего не сделано (или что осталось).
5. Строка без «спроси пользователя» (например, «есть изменения без kit…» при `--check` или в worktree) — передай её и строку `[kit] Синхронизация …` над ней.

Случаи, где нужно действие, а не только флаг:

- **Не совместилось** (код 1 после «Не совместилось само…»): синхронизация остального уже сделана. Сначала передай пользователю строку итога (`[kit] Синхронизация …`, она выше блока «Не совместилось само…»); в ней «Совмещено…» — покажи панель изменений. Затем вопросы по конфликтам: по каждому файлу свой вопрос с `multiSelect: false` (до 4 вопросов в одном вызове AskUserQuestion, больше файлов — группами). В строке файла: «наша» — файл в проекте, «сервера» и «база» — файлы во временной папке (`<папка>/server/…`, `<папка>/base/…`, пути в строке), «нет» — такой версии нет.
  - «Совместить вручную» — правь рабочую копию по версии сервера из временной папки, сохраняя нашу работу; затем покажи панель изменений.
  - «Оставить нашу» — ничего не делай; при следующей синхронизации вопрос повторится, пока наша версия не залита.
  - «Взять версию сервера» — скопируй файл из временной папки в рабочую копию; «сервера — нет» — удали файл.
- **«на сервере нет N из M файлов сайта»** (ничего не записано): «Удалить у нас» — запуск с `--delete-ok`; «Проверить «SSH …»» — остановись, предложи `/kit:project-init`.
- **«Выключил — повторить»** (автозаливка) — запусти команду из варианта.
- **«Не забирать папки»** (больше 50 МБ за раз) — допиши папки из строки «самые тяжёлые папки» в `.gitignore` проекта и запусти скрипт снова: по SSH — как был, без SSH — с `--ftp-done`.
- **Без SSH, «Скачал»** — пользователь скачал папки по FTP в PhpStorm (список и порядок — в выводе): запусти скрипт с `--ftp-done`.
- **Без SSH, правки в рабочей копии** — скачивание затрёт их: «Скачаю всё равно» (`--dirty-ok`) или «Отложить». Согласие — только по ответу пользователя.
- **Без SSH, «Отложить» после скачивания** (автозаливка PhpStorm, объём): не говори «ничего не сделано» — скачанное лежит в проекте незакоммиченным. Скажи это; разобрать его можно позже тем же запуском с `--ftp-done`, вернуть к git — только по просьбе пользователя.
- **«Отменить»** (остановка после записи) — запусти скрипт с `--abort`: он вернёт записанное к HEAD, наши правки не тронет.

## Панель изменений

`mcp__ccd_view__show_pane` с `pane: "diff"` и `diff_scope: "uncommitted"`. Инструмент бывает отложенным — сначала `ToolSearch` с запросом `select:mcp__ccd_view__show_pane`. Инструмента нет — выведи список файлов (`git diff --stat`).

## Не делать

- Не запускай скрипт сам, без просьбы пользователя; не включай его в хуки и в другие навыки.
- Не коммить и не правь индекс git: коммит синхронизации делает скрипт.
- Не повторяй запуск молча после кода 1, 3 или 4: только по ответу пользователя.
- Не добавляй флаги ответа (`--watchers-ok`, `--big-ok`, `--delete-ok`, `--dirty-ok`, `--ftp-done`) без ответа пользователя.
- Не лезь на сервер своими командами: файлы с сервера забирает скрипт.
- Свои правки в `.gitignore` и рабочей копии — только по ответам выше.
