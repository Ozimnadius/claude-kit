# Почему так сделано

Только чтение: ничего не правь, не коммить, в журнал не пиши. Все команды — из корня проекта, без `cd`.

## 1. Где искать

Журнал — параметр «Журнал» в разделе «Параметры для агентов» файла `.claude/CLAUDE.md` (по умолчанию `.claude/docs/progress.md`, в проекте, который ещё не переехал, — `docs/progress.md`); его папка — **папка документов**. Журнала нет — ответ только по git, и скажи, что без журнала причин решений не видно.

Что спросили (аргумент команды или вопрос пользователя):
- **файл** — путь существует;
- **функция** — `путь:имя` (имя функции, метода, класса);
- **строки** — `путь:10-30`;
- **тема** — всё остальное («почему superpowers не убрали», «зачем kit-inbox»).

## 2. Шаги из git (файл, функция, строки)

```
git log --follow --format="%h %ad %s" --date=short -- <путь>
git log -L :<имя>:<путь> --format="%h %ad %s" --date=short -s
git log -L <от>,<до>:<путь> --format="%h %ad %s" --date=short -s
```
ID шага — часть заголовка до первого `: ` (`23.2: …` → `23.2`). Коммит без ID (первый импорт, чужой коммит) — «без шага». Коммитов много — бери самые свежие 10–15 и те, что меняли именно нужное место.

## 3. Журнал по шагам

Для каждого ID (Grep по журналу):
- **строка шага** `| <ID> |` в таблице этапа — что сделано, как проверено, коммит; заголовок раздела `## Этап N — …` — зачем был этап;
- **«Решения»** — в таблице `| № | Дата | Шаг | …` строки с этим шагом (номер, почему, что отвергли); в старой таблице `| Дата | Решение |` — по дате коммита и словам из вопроса;
- **«Баги на потом»** — строки, где упомянут шаг («исправлен на шаге …») или файл;
- **сверка этапа** — строка «Сверка …» под таблицей этапа;
- **документы этапа** — раздел «Документы» журнала: план или спек этого этапа (`work/…`, `archive/…`); в нём — Grep по ID шага или словам вопроса.

## 4. Тема

Сразу журнал: «Решения» (сначала), затем таблицы этапов, баги, «Сейчас»; документы из реестра (спек, планы) — Grep по словам вопроса и их синонимам. Затем коммиты: `git log --format="%h %ad %s" --date=short -i --grep=<слово>`.

## 5. Если история неполная

- Хеш из журнала не находится (`git cat-file -e <хеш>` — код не 0): история могла быть переписана или свёрнута — опирайся на строку журнала и прямо скажи, что коммита в репозитории нет.
- Шаг есть в git, но не в журнале (или наоборот) — так и напиши.
- Причины нигде нет — «в истории причина не записана»; не додумывай. Догадку, если она полезна, помечай словом «вероятно» и отделяй от подтверждённого.

## 6. Ответ

Коротко:
1. 2–5 фраз «почему», у каждой — ссылка в скобках: шаг, коммит, решение, документ — `(шаг 23.2, коммит 0b9e27e, решение №7)`, `(archive/plan-history.md, задача 21.3)`.
2. **Источники** — список: шаги с датами и заголовками коммитов, номера решений, документы.
3. **Не нашёл** — чего в истории нет (если есть пробелы).

Хронологию по датам («как менялось») — только если пользователь попросит подробнее.
