# Отчёт для заказчика

Читаешь журнал, git и план выкладки; ничего не правишь и не коммитишь. Единственная запись — заметка во входящие в конце (п. 5). Все команды — из корня проекта, без `cd`.

Журнал и план выкладки — параметры «Журнал» и «План выкладки» в разделе «Параметры для агентов» файла `.claude/CLAUDE.md` (по умолчанию `.claude/docs/progress.md` и `deploy-prod.md` рядом с ним). Журнала нет — отчёт не из чего собрать: предложи `/kit:project-init`.

**Журнал по частям** (рядом с журналом есть папка `journal/`, с kit 2.13): в журнале — «Сейчас», оглавление «Этапы», «Документы», «Прод: не забыть» и текущий этап; «Решения» — `journal/decisions.md`, «Баги на потом» — `journal/bugs.md`, «Справочник» и «Материалы заказчика» — `journal/reference.md`, закрытые этапы — `journal/stages/stage-NN.md`. Ищи и там: Grep по папке документов, а не только по журналу.

## 1. Период

- Дата в аргументе — с неё.
- Иначе — с прошлого отчёта: самая поздняя дата из строк «Отчёт заказчику: ГГГГ-ММ-ДД …» в «Справочнике» журнала и из заметок во входящих (ещё не записанных в журнал):
  ```
  node "${CLAUDE_PLUGIN_ROOT}/scripts/decision-inbox.js" --list
  ```
  Отчёт в этот же день уже был — бери его дату: в период попадёт и сегодняшнее.
- Отчётов не было — с начала текущего этапа: «начат ГГГГ-ММ-ДД» в «Сейчас» журнала, а нет — дата первого коммита этапа (`git log --reverse --format="%ad %s" --date=short`, первый с ID этого этапа).
- Конец периода — сегодня. Период назови в первой строке отчёта.

## 2. Данные

- **Сделано** — коммиты за период:
  ```
  git log --since=<дата> --format="%ad %s" --date=short
  ```
  ID шага — часть заголовка до первого `: `. По каждому ID — строка шага в журнале («Что сделано», «Как проверено») и заголовок этапа. Шаги `⏳` того же этапа — «в работе». Коммит шага ищи по ID в начале заголовка (`git log --format="%h %s"`, строка `<ID>: …`), а не по столбцу «Коммит» журнала: с kit 3.0 хешей в журнале нет.
- **Выложено на сайт** — при «Выкладка: PhpStorm Always» — шаги, закоммиченные в периоде (автозаливка увезла их сразу, строк «Залито» нет); при «вручную» и «Claude по SSH» — строки «Залито на прод» (при «Окружение: дев» — «Залито на дев») плана выкладки с датой в периоде; плана нет (параметр `—`) — раздел пропусти.
- **Подтвердить** — «Решения» с датой в периоде, которые касаются заказчика: внешний вид и поведение сайта, данные, формы и CRM, сроки, отказ от того, о чём просили. Особенно «Кто: агент» — их заказчик ещё не видел. Внутренние решения о процессе и инструментах (как делаются коммиты, где лежат документы) не включай.
- **Открытые вопросы** — только из этих разделов: «Баги на потом» без `✅`, которые касаются сайта, «Блокеры и открытые вопросы» из «Сейчас», невыполненное из «Прод: не забыть». Из описаний шагов не бери («после коммита — push … с согласия» — внутренний порядок работы, к отчёту уже выполнен).
- **Дальше** — «Следующий шаг» из «Сейчас».

## 3. Язык

**От имени пользователя:** первым лицом, как он сам написал бы в задаче — «сделал», «поправил», «выложил», а не «было сделано», «выполнены работы», «Claude» или «мы с агентом».

**Неформально, как коллеги между собой:** просто и по-живому, без канцелярита («в рамках», «осуществлена», «произведены работы», «Уважаемые…», «Довожу до сведения») — но без панибратства и смайлов. Обращение — как в переписке задачи; не видно — на «вы».

**Общими словами, без деталей:** пиши для обычного человека, не для разработчика — что изменилось для сайта и посетителей, понятно без знания IT. Шаги одной задачи — один пункт, мелочи — одним пунктом («поправил мелочи в вёрстке каталога»). Пункт — одно короткое предложение; в «Сделал» — не больше 5–7 пунктов; весь отчёт читается за полминуты.

**Не включай никогда:** хеши коммитов, ID шагов, пути и имена файлов, функций и классов, названия агентов, скриптов и плагина, адреса серверов, логины, пароли, ключи, IP. Можно: страницы сайта (адрес или название), номер задачи Битрикс24, даты.

**Без кухни разработки:** не пиши про git, коммиты, тесты и их число, проверки инструментами, размеры файлов и лимиты. Из «Как проверено» бери только то, что видно заказчику (какие страницы и на каких экранах проверены); остальное — не упоминай.

## 4. Отчёт

Текстом в чат, готовым для копирования в задачу Битрикс24 или письмо. Раздел без пунктов не выводи.

```
Привет! Коротко, что по <задача или сайт> за <ДД.ММ>–<ДД.ММ.ГГГГ>.

Сделал
- …

Уже на сайте
- ДД.ММ — …

Нужно ваше «ок»
- … (почему сделал так; можно и иначе — …)

Пока открыто
- …

Дальше
- …
```

Всё сделанное уже на сайте — вместо раздела «Уже на сайте» одна строка после «Сделал»: «Всё уже на сайте.»

Сохранить файлом — только по просьбе: `<папка документов>/work/report-ГГГГ-ММ-ДД.md` и строка `DOCS` в следующем `/kit:step-done`.

## 5. Запомнить дату

После отчёта:
```
node "${CLAUDE_PLUGIN_ROOT}/scripts/decision-inbox.js" --note "Отчёт заказчику: <сегодня ГГГГ-ММ-ДД> (период с <ГГГГ-ММ-ДД>)"
```
Следующий `/kit:step-done` передаст заметку в `NOTES`, и `kit-journal.js` запишет её в «Справочник» — по ней следующий отчёт начнётся отсюда.
