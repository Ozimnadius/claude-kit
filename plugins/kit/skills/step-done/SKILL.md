# Закрытие шага

Закрывай только проверенный шаг: тесты, `php -l`, результат на сервере или в браузере — что положено по правилам проекта. Все команды — из корня проекта, без `cd`.

## 1. Подготовка

```
node "${CLAUDE_PLUGIN_ROOT}/scripts/kit-step.js" <STEP>
```
Только читает. Код 2 — не kit-проект, нет журнала или старый формат: покажи вывод и предложи `/kit:project-init` (переезд на формат kit 3.0), шаг не закрывай. Код 4 — неверные аргументы.

По выводу:
- **Файлы шага** — пути для коммита. Что-то к шагу не относится или незнакомо — спроси через AskUserQuestion: «В этот коммит» / «Оставить как есть». **Не пойдут в коммит** — их скрипт коммита не пропустит: не включай, скажи пользователю.
- **Входящие** — готовые строки DECISIONS и NOTES и `входящих: N` (N — для `--inbox`, п. 5).
- **Режим**: в строке выкладки или документов есть `reference/ssh.md` — прочитай `${CLAUDE_PLUGIN_ROOT}/skills/step-done/reference/ssh.md` и иди его порядком; `удалённый репозиторий: <имя>` — для `--push` (п. 5).
- Шаг закрывает этап — передан `STAGE`, номер этапа в `NEXT` (часть ID до первой `.`) другой или `NEXT` — `—` при `STEP` вида `N.M`: до п. 3 прочитай `${CLAUDE_PLUGIN_ROOT}/skills/step-done/reference/stage-close.md` (сверка и архив).

## 2. Блоки

Из разговора и вывода подготовки:
- обязательные: `STEP` — ID шага (аргумент команды, если передан); `STATUS` — `✅` / `⏳` / `⏸` / `❌`; `SUMMARY` — одна строка: что сделано; `CHECK` — одна строка: как проверено (команды, страницы, ширины, итог), при `✅` обязателен; `NEXT` — `ID — строка` или `—`;
- необязательные: `STAGE` (`N — название` — начинается новый этап), `BLOCKERS` (новый текст пункта «Блокеры и открытые вопросы» целиком), `DECISIONS`, `DOCS`, `BUGS`, `PROD_TODO`, `NOTES`, `DEPLOY`, `RECONCILE` (из `reference/stage-close.md`).

`DECISIONS` — по строке: `ГГГГ-ММ-ДД | решение | почему | что отвергли (или —) | пользователь / агент`.
- Из входящих — реальные решения. Процедурные ответы («закрывать?», «начинать?», «коммитить?», подтверждения, выбор порядка работы) отбрось. «Почему» — описание выбранного варианта, «что отвергли» — другие варианты: kit-step.js уже собрал строку; причины нет — `—`, отдельно не спрашивай. Свой ответ («(свой ответ)») — по смыслу: встречный вопрос или уточнение — не решение.
- Решения агента — только трудно откатываемые или влияющие на следующие шаги (подход, библиотека, место хранения, отказ от варианта), 1–3 за шаг.
- Решение отменяет прежнее — текст начинается с «Заменяет №N» (номер из таблицы решений журнала).
- Правило проекта поменялось — правь `.claude/CLAUDE.md` сам, одной правкой (Edit), и добавь строку `ГГГГ-ММ-ДД | Правило: <что изменилось> | <почему> | — | пользователь`; `.claude/CLAUDE.md` — в пути коммита.

`DOCS` — `<путь от папки документов> — <о чём> — <статус>`. Новый документ в `work/` — `в работе, этап N`; документ на все этапы (спек, замечания пользователя) — `постоянный`; ставший ненужным — `устарел — <чем заменён>`. Документы — только в `work/` папки документов.

`BUGS` — `<№> | <баг> | <где> | <статус>`: новый баг без номера — `— | …` (номер даст скрипт), смена статуса — `К61 | | | ✅ <STEP>`.

`DEPLOY` — строки `- Поле: значение`: `Файлы`, `Коммит`, `Проверка` — строка в «Залито на прод» или «Залито на дев» (при автозаливке PhpStorm не пишется), её пишет шаг, на котором пользователь сообщил о ручной выкладке; `Удалить` — `путь — почему`; `Чек-лист` — пункт переключения.

`NOTES` — факты для справочника; «Заказчик: …» — в материалы заказчика; заметки из входящих — дословно. Снимки `/kit:visual` — метки, сравнение и итог, путь к `report.html`; снимки `<папка документов>/visual/` в коммит не идут, `.claude/scripts/visual/pages.json` — идёт.

## 3. Журнал

Одной командой **Bash** (не PowerShell); блоки — heredoc с кавычками `<<'KIT_BLOCKS'`, Bash вставляет текст как есть:
```
node "${CLAUDE_PLUGIN_ROOT}/scripts/kit-journal.js" <<'KIT_BLOCKS'
STEP: <ID>
STATUS: ✅
SUMMARY: …
CHECK: …
NEXT: <ID> — …
DECISIONS:
- …
KIT_BLOCKS
```
Однострочный блок — `КЛЮЧ: значение`, многострочный — `КЛЮЧ:` и строки `- …` до следующего ключа.
- Код 0 — записано. Вывод: раздел «Сейчас» после правки и **Изменены файлы** — пути для коммита.
- Код 1 — записано, есть предупреждения: покажи их пользователю (нет строки шага в чек-листе плана — проверь ID).
- Код 4 — неверные блоки: исправь и повтори. Код 2 — ничего не записано (старый формат, этап уже перенесён, таблица не разбирается): покажи причину и остановись.

Повтор с теми же блоками ничего не удваивает.

## 4. Просмотр перед коммитом

Коммит — только после просмотра пользователем.
1. **Покажи изменения.** `mcp__ccd_view__get_layout` — запомни, есть ли `diff` в `open_panes`; затем `mcp__ccd_view__show_pane`: `pane` — `diff`, `diff_scope` — `uncommitted` (инструменты панелей бывают отложенными — ToolSearch `select:mcp__ccd_view__show_pane,mcp__ccd_view__close_pane,mcp__ccd_view__get_layout`). Инструментов нет (терминал, IDE) — `git -c core.quotepath=false diff --stat -- <пути>` и список новых файлов в чат.
2. **Коротко в чате:** что сделано, файлы с числом добавленных и удалённых строк, заголовок будущего коммита; вопрос к строке — клик в панели и комментарий, отправить все — Ctrl+Enter.
3. **Вопрос** через AskUserQuestion: «Коммитить» (задан удалённый репозиторий — «Коммитить и отправить») / «Есть вопросы — оставлю комментарии» / «Не коммитить пока». Ответ процедурный, в DECISIONS не идёт. Порядок SSH — варианты из `reference/ssh.md`.
4. **Комментарии** приходят сообщением: файл, строка, текст. Ответь на каждый. Правишь по ним код — это часть шага: проверь заново; изменились SUMMARY или CHECK — снова `kit-journal.js` только со строками шага (`STEP`, `STATUS`, `SUMMARY`, `CHECK`, `NEXT`). Затем снова п. 1.
5. Просят не коммитить какой-то файл — убери его из путей коммита и скажи, что он останется незакоммиченным.
6. «Не коммитить пока» — остановись: правки и журнал остаются, входящие не трогай. Скажут коммитить — продолжи с п. 4.1, журнал заново не пиши.
7. **Закрой панель**, которую открыл, — `mcp__ccd_view__close_pane`, `pane` — `diff`: после «Не коммитить пока» сразу, после «Коммитить» — когда коммит прошёл или остановился. Пока идёт разговор по комментариям и если панель была открыта до п. 1 — не закрывай.

## 5. Коммит

Одной командой **Bash** (не PowerShell). Сообщение — heredoc с кавычками `<<'KIT_MSG'`: `$`, обратные кавычки и `\` не подставляются, перепечатки нет.
```
node "${CLAUDE_PLUGIN_ROOT}/scripts/kit-commit.js" --inbox <N> [--push <имя>] -- "<путь1>" "<путь2>" … <<'KIT_MSG'
<STEP>: <суть шага одной строкой>

<CHECK дословно>

<строка Co-Authored-By>
KIT_MSG
```
- Пути — файлы шага (п. 1) и «Изменены файлы» из вывода `kit-journal.js`, каждый — отдельным аргументом в двойных кавычках. `--inbox` — N из подготовки (входящих нет — флаг не нужен); `--push` — имя из строки «удалённый репозиторий», если он задан.
- Строка `Co-Authored-By: …` — из твоих собственных системных инструкций о подписи коммитов, дословно; таких инструкций нет — строки и пустой строки перед ней нет.

Скрипт проверяет пути и секреты, делает один коммит, сверяет его (сообщение побайтно, путей шага нет в `git status`), затем убирает N входящих и отправляет.
- Код 0 — коммит сделан и проверен (и отправлен, если просили).
- Код 1 — остановила проверка путей или секретов: покажи вывод (значения замаскированы); индекс оставлен как есть — после исправления та же команда.
- Код 2 — ошибка (git, хук, неверный путь): покажи вывод, коммита нет.
- Код 3 — коммит есть, но самопроверка нашла расхождение: покажи вывод, историю не чини.
- Код 4 — коммит сделан и проверен, но не отправлен: прочитай `${CLAUDE_PLUGIN_ROOT}/skills/step-done/reference/push.md`.

Историю сам не чини: никаких `reset`, `amend`, `rebase`. Коммит в обход скрипта не делай ни при каких обстоятельствах — сообщи о проблеме и остановись.

## 6. Ответ пользователю

Коротко: хеш и заголовок коммита (первая строка вывода `kit-commit.js`), отправлен ли он (`<имя>/<ветка>` или почему нет), раздел «Сейчас» из вывода `kit-journal.js`.

Записаны решения агента — отдельным списком «Решения агента на этом шаге (можно возразить)»: решение и почему. Нет — списка не выводи. Пользователь возразил — новое решение («Заменяет №N») запишет следующий шаг.
