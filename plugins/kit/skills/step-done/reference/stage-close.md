# Закрытие этапа

Шаг закрывает этап, если номер этапа в `NEXT` (часть ID до первой `.`) отличается от номера в `STEP` или `NEXT` — `—`; для ID не вида `N.M` (`Р6а`) — передан `STAGE`. `STAGE` на первом шаге нового этапа (прежний уже закрыт и перенесён) этап не закрывает. До журнала (п. 3 ядра) — сверка и архив, перед коммитом — перенос этапа.

## 1. Сверка

1. **С чем сверять.** Раздел «Документы» журнала: строки `work/…` со статусом `в работе, этап <номер закрываемого этапа>` — спек (разделы «Требования», «Критерии готовности»), план (задачи). Пункты — требования Т-N и критерии или задачи плана. Таких документов нет — пункты только из таблицы этапа: шаги не `✅` (⏳, ⏸) — расхождения; все `✅` — «расхождений нет», без вопросов.
2. **Таблица сверки** — в ответе пользователю: `| Пункт | Шаги | Итог |`, итог — сделано / частично / нет / не просили (сделано сверх задуманного). Опирайся на таблицу этапа и коммиты; не уверен — «частично» с пояснением, не «сделано».
3. **Расхождения** (частично, нет) — один AskUserQuestion, список — в тексте вопроса: «В «Баги на потом» (Рекомендую)» / «На следующий этап» / «Не делаем — решением»; разное для разных пунктов — через «Другое». «В Баги» — строки `BUGS`; «Не делаем» — строки `DECISIONS` (почему — из ответа, нет причины — `—`); «На следующий этап» — в блок `RECONCILE`.
4. **Итог** — блок `RECONCILE` для журнала (строка под таблицей этапа):
   ```
   RECONCILE: ГГГГ-ММ-ДД | этап N | сверено с: <документы или «таблица этапа»> | пунктов M, сделано K | расхождения: <пункт — куда; …> или нет | на следующий этап: <пункты> или —
   ```

## 2. Архив

Кандидаты — строки `work/…` раздела «Документы» со статусом `в работе, этап <номер закрываемого этапа>` (`постоянный` кандидатом не бывает). Нет — ничего не спрашивай. Есть — AskUserQuestion, список файлов — в тексте вопроса: «Все в archive/ (Рекомендую)» / «Оставить в work/»; часть — через «Другое». Оставленные в `work/` — строка `DOCS` со статусом `в работе, этап <номер следующего этапа>`: при закрытии следующего этапа их предложат снова. Выбранное в архив перенеси обычным перемещением, без git:
```
New-Item -ItemType Directory -Force '<папка документов>/archive' | Out-Null
Move-Item -LiteralPath '<папка документов>/work/<имя>' -Destination '<папка документов>/archive/<имя>'
```
Папка-документ (`work/design/`) переносится целиком; имя в `archive/` занято — спроси пользователя, файлы не перезаписывай. В `DOCS` — `archive/<имя> (было work/<имя>) — <о чём> — готово, этап N (ГГГГ-ММ-ДД)`: галочку последнего шага `kit-journal.js` поставит уже в `archive/<имя>`. В пути коммита — **оба** пути, старый и новый: скрипт коммита добавит их одной командой `git add -A -- …`, и git увидит переименование — коммит шага остаётся одним. Документ не был в git (`git ls-files <старый путь>` пусто) — только новый путь: `git add` по неотслеживаемому старому пути остановил бы скрипт коммита.

## 3. Перенос этапа

После ответа «Коммитить» (в порядке SSH — после записи журнала), перед заливкой документов (`--docs`) и коммитом перенеси раздел закрытого этапа в его файл — сверка уже под таблицей этапа. Раньше нельзя: в перенесённый этап `kit-journal.js` не пишет (код 2), и правку шага по комментариям было бы не записать.
```
node "${CLAUDE_PLUGIN_ROOT}/scripts/journal-split.js" --stage <N>
```
Код 2 — стоп, покажи ошибку (скрипт ничего не записал). Код 0 — `journal/stages/stage-NN.md` и журнал — в пути коммита.
