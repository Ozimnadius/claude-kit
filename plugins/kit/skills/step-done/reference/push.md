# Коммит не отправлен — код 4 `kit-commit.js`

Коммит сделан и проверен, но в удалённый репозиторий не ушёл. Отправка — без `--force`, `pull` и `rebase`; во всех случаях коммит остаётся локально, историю сам не чини. Причина — в строке «kit-commit: не отправлено — …»:

- **нет сети, входа или вышло время** — скажи причину одной строкой (последняя строка вывода git). Не повторяй: неотправленное уйдёт со следующим шагом, а при старте сессии хук напомнит. Окно входа Git Credential Manager — для пользователя: пароли и токены не вводи и не вписывай в адрес.
- **на удалённом есть коммиты, которых здесь нет** (работали с другого компьютера, или репозиторий создан не пустым) — стоп: скажи пользователю и спроси через AskUserQuestion, что делать. `--force`, `pull`, `rebase` и слияния — только после его явного выбора.
- **удалённый репозиторий отклонил отправку** (хук сервера или защита ветки) — покажи строки `remote:` и последнюю строку вывода git; повтор, `pull` и `--force` не помогут — права и защиту ветки настраивает пользователь, неотправленное уйдёт со следующим шагом.
- **в истории секреты** (первая отправка: в истории ветки пароль, вебхук, ключ) — не отправляй: покажи находки из вывода (значения замаскированы, впереди — хеш коммита) и скажи, что секрет остался в истории: убрать его из истории или начать новый репозиторий с текущего состояния — решает пользователь; историю сам не переписывай.
- **в истории запрещённые пути** (в истории были файлы вроде `.idea/…` или `docs/visual/.gitignore`) — покажи список и спроси через AskUserQuestion: «Отправить как есть» / «Не отправлять». В вопросе предупреди: `.settings.php`, `.settings_extra.php`, `dbconn.php`, `.env`, `*.key`, `*.pem` обычно хранят пароли и ключи — если такие есть в списке, рекомендуй «Не отправлять». «Отправить как есть» — `git push -u <имя> HEAD`.
