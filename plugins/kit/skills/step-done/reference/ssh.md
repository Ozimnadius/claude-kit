# Порядок «Claude по SSH»

Читай, когда в выводе `kit-step.js` строка выкладки — «Claude по SSH — Залить N, Удалить M; порядок SSH» или строка документов — «да — перед коммитом заливка --docs». На сервер шаг уезжает только отсюда — после просмотра пользователем; до этого проверяется только локальное (`php -l`, тесты). Все команды — из корня проекта.

## Порядок шага

1. Подготовка и блоки — п. 1–2 ядра.
2. Есть что заливать («Залить N, Удалить M») — **порядок SSH**: просмотр с «Залить на сервер» (ниже) → заливка и проверка на сервере → журнал (п. 3 ядра; CHECK — с итогом заливки и проверки) → документы на сервере (при «да») → коммит (п. 5 ядра). «Нечего заливать» (шаг меняет только документы) — обычный порядок ядра, а при «Документы на сервере: да» перед коммитом — заливка документов (ниже). Файлы шага скачаны с сервера — не заливка, а точка отсчёта (раздел «Файлы взяты с сервера»).
3. Изменения, не относящиеся к шагу: заливка берёт всю папку проекта — они уедут на сервер вместе с ним, поэтому «оставить как есть» не годится: AskUserQuestion «В этот шаг (уедут на сервер и в коммит)» / «Остановиться — разберусь с ними».
4. В выводе подготовки блок «Пропущено — не файл» (подмодуль или вложенный git-репозиторий) — повтор не поможет: AskUserQuestion «Добавить в «Не выкладывать» (Рекомендую)» / «Остановиться». Добавить — допиши путь в параметр «Не выкладывать» `.claude/CLAUDE.md` (это часть шага, файл — в пути коммита) и снова `kit-step.js`.

## Просмотр

Как п. 4 ядра, но перед каждым вопросом — свежий сухой прогон (после правок по комментариям список мог измениться):
```
node "${CLAUDE_PLUGIN_ROOT}/scripts/ssh-deploy.js"
```
В чате — что уедет: сервер, «Залить (N)», «Удалить (M)». Варианты: «Залить на сервер» (в описании: после проверки на сервере — коммит, а при заданном «Удалённом репозитории» — и отправка; без нового вопроса) / «Есть вопросы — оставлю комментарии» / «Не заливать пока». Ответ «Залить на сервер» включает и заливку документов.

- Правки по комментариям: в порядке SSH журнал ещё не записан — передавать нечего, исправленное уйдёт в запись после заливки.
- Просят не коммитить файл — он уезжает на сервер всё равно (заливка берёт папку проекта); не заливать его можно, только вернув к прежнему виду до заливки (с согласия).
- «Не заливать пока» — остановись: правки остаются, журнал ещё не записан; скажут продолжить — снова просмотр.

## Заливка и проверка на сервере

После ответа «Залить на сервер»:
1. **Заливка:**
   ```
   node "${CLAUDE_PLUGIN_ROOT}/scripts/ssh-deploy.js" --go
   ```
   Код 0 — дальше. Код 1 (часть не вышла: не записан, md5 не совпал, на сервере нет `base64` или `md5sum`) или 3 (нет подключения, обрыв, вышло время) — покажи причину; повтор безопасен (та же заливка даёт тот же результат) — AskUserQuestion «Повторить заливку» / «Остановиться». Код 1 только из-за «Пропущено — не файл» — повтор не поможет: как в п. 4 порядка. Остановились — коммита нет, правки остаются. Код 2 или 4 — покажи вывод и стоп.
2. **Проверка на сервере** — сам, по правилам проекта: страница на десктопе и мобильной ширине одним пакетным вызовом браузера (`browser_batch`: открыть, снимок на десктопе, мобильная ширина, снимок; снимки уменьшенные).
3. **Не прошла** — правка (это часть шага), локальные проверки, затем снова просмотр → заливка → проверка. Правки — не решения, в DECISIONS не идут.
4. **Прошла** — журнал (п. 3 ядра): CHECK — с итогом заливки («Залито и сверено…») и проверки на сервере; `DEPLOY` — `Файлы:` — строка «DEPLOY Файлы:» из вывода `--go` без этих слов, `Проверка:` — как проверено; `Коммит` не передавай: ячейка останется пустой, скрипты найдут коммит по ID шага. Затем документы (при «да») и коммит — без нового вопроса.
5. **Отказ от шага** — проверка не прошла, а пользователь просит откатить, а не править: сначала запомни пути из вывода `--go` («Залить» и «Удалить»), затем верни их локально к прежнему виду (с согласия: правки — `git checkout -- <путь>`, новые файлы шага — удалить, удалённые — вернуть из `HEAD`) и верни сервер теми же путями:
   ```
   node "${CLAUDE_PLUGIN_ROOT}/scripts/ssh-deploy.js" --go -- <пути>
   ```
   Что есть на диске — зальётся в прежнем виде, чего нет — удалится на сервере. Просто откатить файлы локально нельзя: после этого скрипт скажет «Нечего заливать», а на сервере останется отвергнутая версия. Коммита у шага нет, журнал не пиши; скажи пользователю, что сервер возвращён.

## Файлы взяты с сервера — точка отсчёта без заливки

Шаг принёс в проект файлы, скачанные с сервера (`tar` по SSH, Remote Host PhpStorm): рабочие папки в `bitrix/` после обновления ядра или решения, итог сверки на сервере, справочную копию. Заливать их незачем — на сервере они такие же; заливка лишь сменила бы даты файлов или затёрла бы то, что успело измениться на сервере. Вместо неё — **точка отсчёта**: строка в «Залито на …» без заливки, и следующая заливка считает изменения от коммита этого шага.
1. В шаге — только скачанное: свои правки — отдельным шагом (до или после), иначе они не уедут на сервер.
2. Сверка — ничего не записывает, одно подключение:
   ```
   node "${CLAUDE_PLUGIN_ROOT}/scripts/ssh-deploy.js" --md5
   ```
   Тот же список, что ушёл бы заливкой, сверяется с сервером по md5.
3. **Код 0 — всё совпало.** Просмотр (п. 4 ядра) **обязателен и здесь**: вопроса «Залить на сервер» в этом порядке нет, поэтому без ответа «Коммитить» шаг не коммить. В чате — сервер и число совпавших файлов; варианты «Коммитить — точка отсчёта, без заливки» / «Есть вопросы — оставлю комментарии» / «Не коммитить пока». Затем журнал (п. 3 ядра): CHECK — с итогом сверки («md5 совпали: N из N, не заливались»), `DEPLOY` — `Файлы:` — строка «DEPLOY Файлы:» из вывода без этих слов, `Проверка:` — как сверили; `Коммит` не передавай (скрипты найдут коммит по ID шага). Затем документы (при «да») и коммит.
4. **Код 1 — есть различия:** «Отличаются», «Нет на сервере», «Удалены локально, а на сервере есть» — покажи список. AskUserQuestion: «Скачать эти файлы заново» (Рекомендую: сервер изменился после скачивания) / «Залить их — порядок SSH» (на сервере нужна локальная версия) / «Остановиться». Код 3 (нет подключения) — повтор безопасен; код 2 или 4 — покажи вывод и стоп.

## Документы на сервере

Только при «Документы на сервере: да» — в любом порядке шага, сразу перед коммитом, после переноса этапа (если шаг закрывает этап, `stage-close.md`, п. 3): журнал и другие документы шага к этому времени уже записаны.
```
node "${CLAUDE_PLUGIN_ROOT}/scripts/ssh-deploy.js" --go --docs
```
Уезжают `.claude/.htaccess` (первым), `.claude/CLAUDE.md` и `.claude/docs` без снимков `visual` — изменённые с последней заливки; удалённые в git — удаляются на сервере. Нового вопроса нет: заливку документов включают ответы «Коммитить» и «Залить на сервер».
- Код 0 (и «Нечего заливать») — коммит.
- Код 1 или 3 — покажи причину; повтор безопасен — AskUserQuestion «Повторить заливку документов» (Рекомендую) / «Остановиться». Остановились — коммита нет: правки, журнал и уже залитый код остаются; скажут продолжить — снова эта заливка, затем коммит, журнал заново не пиши. Коммита без документов нет: следующая заливка считает от коммита шага, и незалитые документы на сервер уже не попали бы.
- Код 2 (параметр не «да» или нет `.claude/.htaccess`) — покажи вывод и стоп: предложи `/kit:project-init`. Код 4 — покажи вывод и стоп.
