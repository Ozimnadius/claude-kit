## Как работаем

- **Код пишет Claude.** {{Один шаг за раз: код во временной папке → `php -l` → запись в проект → проверка результата на сервере одним пакетным вызовом браузера (`browser_batch`: открыть, снимок на десктопе, мобильная ширина, снимок; снимки уменьшенные) → следующий шаг. | Один шаг за раз: код → `php -l` → запись в проект → `/kit:step-done`: просмотр, заливка по SSH, проверка результата на сервере одним пакетным вызовом браузера (`browser_batch`: открыть, снимок на десктопе, мобильная ширина, снимок; снимки уменьшенные), коммит → следующий шаг.}}
- **Выбор** за пользователем, вопросы — только через AskUserQuestion.
- **Документы** — в `.claude/docs/`: журнал и план выкладки в корне; планы, спеки, чек-листы, материалы задач — в `work/`; готовое и устаревшее — в `archive/`; реестр — раздел «Документы» журнала (новый документ — строкой DOCS в `/kit:step-done`, в архив — при закрытии этапа).
- **Крупная задача** — `superpowers:brainstorming` и `writing-plans` по правилам kit: спека и план — в `.claude/docs/work/` (`spec-<тема>.md` по шаблону kit, `plan-<тема>.md` с разделом «Чек-лист» в начале: строка на задачу `- [ ] N.M — …`, шаги внутри задач — без чекбоксов; закрытые шаги отмечает `/kit:step-done`), не в `docs/superpowers/`; сам superpowers не коммитит — задача плана = шаг kit, коммит через `/kit:step-done`; выбранный подход и отвергнутые — в «Решения»{{; без отдельных веток и worktree — правки из них не дойдут до сервера автозаливкой | (строки про ветки нет — автозаливки нет)}}.
- **После проверки шага** — `/kit:step-done`: скрипт `kit-journal.js` обновляет журнал и план выкладки, `kit-commit.js` делает один коммит `ID: …`.
- **Git** пользователь сам не трогает, команды git ему не выдаём.
- **Форматирование:** файлы целиком не переформатировать. Переводы строк — LF.
