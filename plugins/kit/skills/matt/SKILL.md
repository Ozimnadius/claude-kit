# Большая работа по системе Мэтта

Навыки Мэтта — с префиксом `mattpocock-skills:`; `implement-spec` и `setup-matt-pocock-skills` не используются. Вопросы пользователю — только через AskUserQuestion. Правила kit сильнее текста навыка Мэтта.

Навыки только по команде (`wayfinder`, `to-spec`, `to-tickets`, `implement` и др.) — читай файлом:
```
node "${CLAUDE_PLUGIN_ROOT}/scripts/matt-skill.js" <имя>
```
Код 0 — путь к `SKILL.md`. Код 2 — плагин не на проекте: `/kit:project-init`. Код 3 — навыка нет (п. 9).

## 1. Когда и маршрут

- Мелкая задача (одна-две сессии) — без карты и тикетов: сделать и закрыть `/kit:step-done`.
- Большая — общая сессия (п. 4). Маршрут — как `mattpocock-skills:ask-matt`: много развилок — карта `wayfinder`; задача ясна — `grill-with-docs` → `to-spec` → `to-tickets`; ясно и мало — сразу сделать. Предложи через AskUserQuestion.
- Карту общая сессия рисует сама по файлу `matt-skill.js wayfinder`, но тикеты `research` — субагентом по заданию п. 5, итог — в тикет; без веток `research/` и `push`.

## 2. Папки и документы

`<docs>` — папка документов, `<тема>` — имя работы.
- `<docs>/work/<тема>/` — `map.md`, тикеты карты `issues/NN-<slug>.md`, `spec.md` (без карты — только он), прототипы HTML.
- `<docs>/work/<тема>-build/` — тикеты реализации `issues/NN-<slug>.md`, правила тикетов `README.md`.
- `<docs>/GLOSSARY.md`, `<docs>/adr/NNNN-<slug>.md` — навсегда; прочие документы — `<docs>/work/`. В корень проекта — ничего. Спек и план kit (`spec-*.md`, `plan-*.md`) не пишутся.
- `DOCS` в `/kit:step-done`: обе папки темы — `в работе, этап <номер этапа реализации>`, тогда закрытие этапа реализации (`reference/stage-close.md`) перенесёт их в `archive/` вместе; глоссарий и ADR — `постоянный`.

## 3. Этапы и шаги

Тикет = шаг `<этап>.<номер тикета>`.
- **Подготовка**, этап N: тикеты карты (номер = номер шага), затем спек и нарезка следующими номерами; без карты — два шага. `map.md` и ещё не взятые тикеты карты — в коммите первого принятого тикета, взятые — каждый в своём. `STAGE: <N> — <тема>: подготовка (система Мэтта, <docs>/work/<тема>/)`.
- **Реализация**, этап N+1: тикеты `<тема>-build/`, номер = номер шага. `STAGE: <N+1> — <тема>: реализация (система Мэтта, <docs>/work/<тема>-build/)`.
- `NEXT` — следующий тикет фронта с путём: `<этап>.<номер> — <заголовок> (<путь тикета>)`.

## 4. Общая сессия

Координатор: очередь, исполнитель на тикет, приёмка (п. 6); тикеты сама не решает, в контекст — только отчёты.
- **Фронт** — открытые, незаблокированные (все из `Blocked by: NN, NN` — `resolved`), не `claimed`; первый по номеру. Статус — `Status: …` в тикетах карты, `**Status:** …` (сначала `ready-for-agent`) в тикетах реализации: меняй в той же форме.
- **Нужен пользователь** (вопросы, оценка: грилинг, спек, нарезка, прототип) — подчинённая сессия `mcp__ccd_session__start_session`: `context` — `fresh`, `use_worktree` — `false`, `initiation` — `user_asked` (с согласия пользователя), `prompt` — задание (п. 5), `background` — тема, папки, решения, `wake_when_done` — `true`. Можно несколько сразу; нет инструмента (терминал) — субагенты. Без карты `grill-with-docs` и `to-spec` — одной сессией: `to-spec` берёт спек из разговора.
- **Остальные** — фоновый субагент (без `isolation`); реализация — по одному, следующий — после приёмки.
- **Отчёт** — коротко; подробности — в тикете.

## 5. Задание исполнителю

Дословно, подставь `<…>`; `[…]` — только субагенту:
```
Тикет <путь> — «<заголовок>». Только этот тикет.
Навык: прочитай <путь из matt-skill.js> и следуй ему (или пользователь введёт /mattpocock-skills:<имя>).
Сначала прочитай: <правила тикетов README.md, если есть>, тикет, разделы спека по его ссылкам, глоссарий <docs>/GLOSSARY.md и ADR <docs>/adr/ в той части, что он задевает.
Возьми тикет: Status: claimed — до начала работы.
Нельзя: коммитить; ветки и worktree; документы вне <docs>/ (GLOSSARY.md, docs/adr, .scratch в корне — нельзя); трогать .idea; ставить пакеты без согласия пользователя.
Вопросы пользователю — через AskUserQuestion, по-русски. [Субагент: вопрос — в ## Comments тикета, Status: ready-for-human, и закончи.]
Готово: допиши в тикет сводку (что сделано, проверки и их итог, файлы), Status: ready-for-human; отчёт — что сделано, файлы, проверки, вопросы.
```
- Спек и нарезка: вместо тикета — папка темы, без строки «Возьми тикет»; сводка — в отчёт.
- Навык — какой называет тикет или карта; реализация — `implement`, её `code-review` — точка `HEAD`, незакоммиченное.
- Субагенту допиши: вопрос — до правок кода; остановился на вопросе — правки только в файле тикета; `code-review` не запускай.

## 6. Приёмка

Только в общей сессии, по одному тикету.
- `/kit:step-done <этап>.<номер тикета>`: просмотр, «Коммитить», один коммит.
- Пути коммита — файлы тикета из отчёта и «Изменены файлы» журнала; файлы идущих тикетов не бери.
- `Status: resolved` — до коммита, в тех же путях: после ответа «Коммитить» (без пользователя — после ревью).
- `DECISIONS` — только ответы этого тикета, по строке на решение: `ГГГГ-ММ-ДД | <решение коротко> | см. <тикет или ADR> | — | пользователь`, без пересказа ответов.
- `--inbox N` — N из `node "${CLAUDE_PLUGIN_ROOT}/scripts/decision-inbox.js" --list` — номер последнего ответа этого тикета (порядок `.claude/kit-inbox.jsonl`, заметки — тоже записи; чей ответ — по вопросу или полю `session`). Заметки до N — в `NOTES`; ответы идущих тикетов до N сохранятся в их тикетах.
- Исправления после замечаний — шагом с буквой (`N.Mа`).
- «Claude по SSH» — заливка и проверка на сервере до коммита, как обычно.

## 7. Без пользователя

Только по слову пользователя. Не включай при «Выкладка: PhpStorm Always» с «Окружение» не «дев». На тикет:
1. Исполнитель — фоновый субагент, задание со строкой «Субагент».
2. Вопрос — тикет уже `ready-for-human`, вопрос в `## Comments`, правки — только в файле тикета: бери следующий незаблокированный.
3. Готово — проверки проекта и ревью навыком `mattpocock-skills:code-review` в общей сессии (сам запускает субагентов): точка — `HEAD`, дифф — `git diff HEAD` и новые файлы тикета, спек — путь тикета. Замечания — исправить, проверки и ревью заново.
4. `/kit:step-done` — разделы 1–3 и 5, раздел 4 (просмотр) пропускается, вопросов раздела 1 не задавай — чужие файлы не бери; в `SUMMARY` — «принят без просмотра», в `CHECK` — итог ревью; пометка и в тикете.
5. «Claude по SSH» — без заливки и `--docs`: её делает разбор по `reference/ssh.md`.
6. Шаг закрывает этап — остановись: сверка и архив спрашивают пользователя.

Между тикетами — расход лимитов (`mcp__ccd_session_mgmt__get_usage`, если есть): остановка до лимита и к сроку пользователя; напиши, где остановился.

## 8. Разбор, когда пользователь вернулся

1. Тикеты «принят без просмотра» — по одному: сводка и `git show --stat <коммит>`; замечания — исправлением по п. 6.
2. Вопросы из `## Comments` — через AskUserQuestion; ответ — в тикет, тикет — в очередь.
3. «Claude по SSH» — одна заливка и проверка на сервере по `reference/ssh.md` шагом с буквой последнего тикета, принятого без просмотра.

## 9. Края

- Файла навыка нет (код 3) — скажи пользователю, предложи ввести `/mattpocock-skills:<имя>` самому, сверь правила kit с версией плагина.
- Исполнитель оборвался — тикет остаётся `claimed`: верни в очередь или спроси пользователя.
- Общие файлы (карта, глоссарий) параллельных тикетов — в коммите тикета допустимы; коммиты — по одному.
- Сжатие контекста — восстанови по «Сейчас» журнала, карте и строкам статуса тикетов.
