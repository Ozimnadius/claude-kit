# Большая работа по системе Мэтта

Только при «Система Мэтта: да» в параметрах, иначе не применяй. Навыки Мэтта — с префиксом `mattpocock-skills:`; `implement-spec` и `setup-matt-pocock-skills` не используются. Правила kit сильнее навыков Мэтта.

Навыки только по команде (`wayfinder`, `to-spec`, `to-tickets`, `implement`, `grill-with-docs`, `triage`, `ask-matt`, `grill-me` и др.) инструментом Skill не вызывай (платформа откажет) — сразу читай файл:
```
node "${CLAUDE_PLUGIN_ROOT}/scripts/matt-skill.js" <имя>
```
Код 0 — путь к `SKILL.md`. Код 2 — плагин не на проекте: `/kit:project-init`. Код 3 — п. 8. Отказ всё же пришёл — пусть пользователь введёт `/mattpocock-skills:<имя>`; без него — вопрос в `## Comments`, `ready-for-human`. Прочие (перечень — в трекере) — Skill `mattpocock-skills:<имя>`.

## 1. Когда и маршрут

- Мелкая задача (одна-две сессии) — без карты и тикетов: сделать и закрыть `/kit:step-done`.
- Большая — общая сессия (п. 4). Маршрут — как `mattpocock-skills:ask-matt`: много развилок — карта `wayfinder`; задача ясна — `grill-with-docs` → `to-spec` → `to-tickets`; ясно и мало — сразу сделать. Предложи через AskUserQuestion.
- Карту рисует общая сессия (`wayfinder`), тикеты `research` — субагент (п. 5).

## 2. Папки и трекер

`<docs>` — папка документов, `<тема>` — имя работы.
- `<docs>/work/<тема>/` — `map.md`, тикеты карты `issues/NN-<slug>.md`, `spec.md`, прототипы HTML.
- `<docs>/work/<тема>-build/` — тикеты реализации `issues/NN-<slug>.md`, правила тикетов `README.md`.
- `<docs>/GLOSSARY.md`, `<docs>/adr/NNNN-<slug>.md` — навсегда; прочее — `<docs>/work/`; в корень проекта — ничего. Спек и план kit (`spec-*.md`, `plan-*.md`) — нет.
- Трекер — по `${CLAUDE_PLUGIN_ROOT}/skills/matt/reference/tracker.md`: прочитай перед картой, нарезкой и первой приёмкой; `/setup-matt-pocock-skills` не предлагай.
- `DOCS` в `/kit:step-done`: обе папки темы с косой в конце (`work/<тема>/`) — `в работе, этап <N+1>` (в `archive/` — вместе); глоссарий и ADR — `постоянный`.

## 3. Этапы и шаги

Тикет = шаг `<этап>.<номер тикета>` без ведущего нуля: `01` → `N.1`.
- **Подготовка**, этап N: тикеты карты, затем спек и нарезка следующими номерами; без карты — два шага. `STAGE: <N> — <тема>: подготовка (система Мэтта, <docs>/work/<тема>/)`.
- **Реализация**, этап N+1: тикеты `<тема>-build/`. `STAGE: <N+1> — <тема>: реализация (система Мэтта, <docs>/work/<тема>-build/)`.
- Шаг не по тикету, пока идёт этап Мэтта (`/kit:project-init`, мелкая задача), — `N.0а`, `N.0б`…
- `NEXT` — следующий тикет фронта: `<этап>.<номер> — <заголовок> (<путь тикета>)`.

## 4. Общая сессия

Координатор: очередь, исполнители, приёмка (п. 6); тикеты не решает, в контексте — только отчёты.
- **Фронт** — открытые, незаблокированные (все из `Blocked by` — `resolved` или `wontfix`), не `claimed` и не `ready-for-human`, не `needs-*`; первый по номеру.
- **Нужен пользователь** (грилинг, спек, нарезка, прототип) — подчинённая сессия `mcp__ccd_session__start_session`: `context` — `fresh`, `use_worktree` — `false`, `prompt` — задание п. 5, `background` — тема, папки, решения (от 80 символов), `wake_when_done` — `true`, `permission_mode` — как у общей. `initiation` — `user_asked` только после ответа пользователя в этом ходе; ход начат событием или запуск отказан — карточка `own_initiative` без `wake_when_done`: пользователь запустит и по окончании напишет «дальше». Несколько сразу — сначала `mcp__ccd_session__mark_chapter`, номера ADR — в задании. Пользователю: в ней на вопрос о правке `.claude` — «разрешить до конца сессии». Без карты `grill-with-docs` и `to-spec` — одной сессией.
- **Событие** (`<side-sessions-event>`, 400 символов) — не конец тикета: принимай, только если тикет `ready-for-human` со сводкой «Готово:» (спек, нарезка — ответ начат с «Готово:»); иначе закончи ход одной строкой.
- **Прочие тикеты** — фоновый субагент: `subagent_type` — `general-purpose`, не fork, без `isolation`; реализация — по одному, следующий — после приёмки.

## 5. Задание исполнителю

Дословно, подставь `<…>`; `[…]` — только субагенту, `{…}` — только реализации:
```
Тикет <путь> — «<заголовок>». Только этот тикет.
Навык: прочитай <путь из matt-skill.js> и следуй ему (или пользователь введёт /mattpocock-skills:<имя>).
Навыки только по команде — файлом (путь выше), инструментом Skill не вызывай; прочие — Skill mattpocock-skills:<имя>.
Трекер: <путь tracker.md>.
Сначала прочитай: <README.md правил тикетов, если есть>, тикет, разделы спека по его ссылкам, <docs>/GLOSSARY.md и <docs>/adr/ в задетой им части.
Возьми тикет: Status: claimed — до начала работы.
Нельзя: коммитить и вызывать /kit:step-done; вызывать /kit:matt; ветки и worktree; новые тикеты, правку и удаление других тикетов и карты (перечисли предложения в отчёте: вопрос, тип, блокеры); документы вне <docs>/ (в корне — ничего); трогать .idea; ставить пакеты без согласия пользователя.
prototype — без шага сохранения в ветку: итог — в тикет, HTML — в <docs>/work/<тема>/; варианты на страницах сайта — только если правки не уходят на прод сами, после выбора — убрать; research — без веток и push. Номера новых ADR — <NNNN>–<MMMM>.
{швы tdd — из спека (Testing Decisions) и тикета, без пользователя отдельно не спрашивай; code-review — точка HEAD, дифф — git diff HEAD -- <файлы тикета> и новые файлы тикета из git status --porcelain (строки ??) списком, не трёхточечный.}
Вопросы пользователю — через AskUserQuestion, по-русски. [Субагент: вопрос — в ## Comments тикета, Status: ready-for-human, и закончи.]
Готово: ответ — в тикет по трекеру, сводка «Готово:» (сделано, проверки и итог, файлы — путями от корня проекта), Status: ready-for-human; отчёт — то же, вопросы, предложения тикетов.
```
- Спек и нарезка: вместо тикета — папка темы, без «Возьми тикет»; нарезке новые тикеты можно; «Готово:» — началом последнего ответа.
- Навык — по `Type:` тикета или `## Notes` карты, не `wayfinder`; реализация — `implement`.
- Субагенту: вопрос — до правок кода; остановился на вопросе — правки только в файле тикета; `code-review` не запускай.

## 6. Приёмка

Только в общей сессии, по одному тикету; вопрос без ответа — не приёмка: AskUserQuestion, ответ — по трекеру.
- `/kit:step-done <этап>.<номер тикета>`: просмотр, «Коммитить», один коммит; в первом принятом — и `map.md`, не взятые тикеты карты.
- Пути — файлы из «Готово:» тикета (не из события; спек и нарезка — `git status --porcelain -uall` папок темы, `GLOSSARY.md`, `adr/`) и «Изменены файлы» журнала, без свёрнутых папок из вывода `kit-step.js` и файлов идущих тикетов.
- До просмотра (раздел 4 `/kit:step-done`), в тех же путях: указатель, новые тикеты, правки карты — по трекеру. После «Коммитить» (без пользователя — после ревью) — только `Status: resolved`, до коммита.
- `DECISIONS` — только ответы этого тикета, по строке на решение: `ГГГГ-ММ-ДД | <решение коротко> | см. <тикет или ADR> | — | пользователь`, без пересказа.
- `--inbox N` — N из `node "${CLAUDE_PLUGIN_ROOT}/scripts/decision-inbox.js" --list` — номер последнего ответа этого тикета (заметки — тоже записи; чей — по вопросу или полю `session` в `.claude/kit-inbox.jsonl`: `--list` его не печатает). Заметки до N — в `NOTES`; ответы идущих тикетов до N сохранятся в их тикетах.
- Исправления после замечаний — шагом с буквой (`N.Mа`).

## 7. Без пользователя

Только по слову пользователя и после его ответа о режиме разрешений; не при «PhpStorm Always» с «Окружение» не «дев». До включения прочитай `${CLAUDE_PLUGIN_ROOT}/skills/matt/reference/autonomous.md` и иди её порядком; вернулся — разбор по ней же.
