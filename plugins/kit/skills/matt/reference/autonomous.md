# Без пользователя и разбор

Читай до включения режима без пользователя (п. 7 ядра `/kit:matt`) и когда пользователь вернулся. Всё остальное — по ядру: фронт, задание (п. 5), приёмка (п. 6). Трекер — `${CLAUDE_PLUGIN_ROOT}/skills/matt/reference/tracker.md`.

## 1. Без пользователя

**Когда.** Только по слову пользователя («работай без меня» и т. п.). Не включай при «Выкладка: PhpStorm Always» с «Окружение» не «дев» — скажи почему.

**Перед включением** — пока пользователь рядом:
1. Режим разрешений. Запись в `.claude` (тикеты, глоссарий, ADR, журнал) в режимах Manual и Accept edits всегда спрашивает разрешение, запрос фонового субагента ждёт в общей сессии — без пользователя работа встанет на первом же запросе. AskUserQuestion «Режим разрешений на время без вас?»:
   - «Auto (Рекомендую)» — правки `.claude` и скрипты kit решает классификатор;
   - «Bypass permissions» — без запросов;
   - «Остаюсь в Manual» — заранее разрешения не выдаются, их дают на первом запросе: тогда первый тикет целиком при пользователе (субагент, ревью, `/kit:step-done`) — на запрос правки `.claude` он отвечает «разрешить до конца сессии», на запуск скриптов kit (`node … kit-*.js`, `decision-inbox.js`) и проверок проекта — «больше не спрашивать»; иначе работа встанет на первом запросе. Не готов ждать — лучше Auto.
   Сменить режим — переключателем режима в приложении (или инструментом смены режима сессии, например `mcp__ccd_session_mgmt__set_session_permission_mode`, если он есть, — после подтверждения пользователя). Ответа нет — режим не включай.
2. Срок: до какого времени работать (без срока — до лимитов, п. «Между тикетами»).
3. На ночь: попроси не усыплять компьютер (сессия идёт, пока он бодрствует) или с согласия — `mcp__ccd_host__request_keep_awake`.

**На тикет:**
1. Исполнитель — фоновый субагент (`subagent_type` — `general-purpose`, не fork), задание п. 5 ядра со строками «Субагент».
2. Вопрос — тикет уже `Status: ready-for-human`, вопрос в `## Comments`, правки — только в файле тикета: во фронт он не входит, бери следующий.
3. Готово — проверки проекта и ревью навыком `mattpocock-skills:code-review` в общей сессии (инструмент Skill; навык сам запускает субагентов): точка — `HEAD`, дифф — `git diff HEAD -- <файлы тикета>` и новые файлы тикета из `git status --porcelain` (строки `??`) списком, не трёхточечный; спек — путь тикета. Замечания — исправить (субагентом по тому же тикету), проверки и ревью заново.
4. `/kit:step-done` — разделы 1–3 и 5, без раздела 4 (просмотр) и вопросов раздела 1 — чужие файлы не бери; файлы — из сводки «Готово:» тикета; в `SUMMARY` — «принят без просмотра», в `CHECK` — итог ревью; пометка и в тикете; указатель в карте и новые тикеты — до `/kit:step-done`, по трекеру; `Status: resolved` — после ревью, до коммита.
5. Отправки нет: без `git push` и `--push` до конца разбора (п. 2, отправка — его п. 4), даже если хук при старте или после сжатия контекста пишет «отправь»: непросмотренные коммиты не уходят в удалённый репозиторий.
6. «Claude по SSH» — без заливки и `--docs`: они — при разборе.
7. Шаг закрывает этап — остановись: сверка и архив спрашивают пользователя.

**Между тикетами** — лимиты: `mcp__ccd_session_mgmt__get_usage`; остановись до лимита (любой из лимитов плана — 80 % и больше) и к сроку пользователя. Данных нет (`not_applicable`, `unavailable`, терминал без инструмента) — не больше 5 тикетов подряд или до срока пользователя. Остановился — скажи, где: последний принятый тикет, тикеты с вопросами, причина.

**Сжатие контекста** — восстанови картину по «Сейчас» журнала, карте и статусам тикетов; снова `node "${CLAUDE_PLUGIN_ROOT}/scripts/matt-skill.js" <имя>` и перечитай файл навыка, которым идёт работа, и эту справку. Если из сводки сжатия не видно, что пользователь разрешил работать без него, — остановись и жди его.

## 2. Разбор, когда пользователь вернулся

1. Тикеты «принят без просмотра» — по одному: сводка и `git show --stat <коммит>`; замечания — исправлением по п. 6 ядра (шагом с буквой), `/kit:step-done` — без `--push`, хотя «Удалённый репозиторий» задан: отправка увезла бы и ещё не разобранные коммиты.
2. Вопросы из `## Comments` — через AskUserQuestion; ответ — в тикет по трекеру, тикет — снова во фронт.
3. «Claude по SSH» — одна заливка и проверка на сервере по `${CLAUDE_PLUGIN_ROOT}/skills/step-done/reference/ssh.md` шагом с буквой последнего тикета, принятого без просмотра.
4. «Удалённый репозиторий» — когда разобраны все тикеты «принят без просмотра» (п. 1): `--push` ближайшего `/kit:step-done` (при «Claude по SSH» — шага заливки п. 3).
5. Режим разрешений, включённый на время без пользователя, — вернуть, если он захочет (переключателем в приложении).
