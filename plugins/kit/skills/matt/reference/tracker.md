# Трекер задач проекта Мэтта — локальные файлы

Источник: `setup-matt-pocock-skills/issue-tracker-local.md` и `triage-labels.md` из mattpocock-skills 1.3.1 (Matt Pocock, лицензия MIT), переложено на места и статусы kit.

Это и есть «док трекера» и словарь меток, которых ждут навыки Мэтта (`wayfinder`, `to-spec`, `to-tickets`, `triage`, `code-review`): `/setup-matt-pocock-skills` не предлагай и не запускай, `docs/agents/` и `.scratch/` не заводи. Где навык говорит об issue, метке или комментарии — делай по этой справке. Правила kit сильнее текста навыка.

## 1. Места

`<docs>` — папка документов проекта (обычно `.claude/docs`), `<тема>` — короткое имя большой работы.

- Карта — `<docs>/work/<тема>/map.md`; тикеты карты (решения) — `<docs>/work/<тема>/issues/NN-<slug>.md`; спек — `<docs>/work/<тема>/spec.md`; прототипы HTML и итоги исследований (если не влезают в тикет) — `<docs>/work/<тема>/`, ссылкой из тикета.
- Тикеты реализации — `<docs>/work/<тема>-build/issues/NN-<slug>.md`; правила тикетов — `<docs>/work/<тема>-build/README.md`. К тикетам карты их не клади: обе нумерации — с `01`.
- Номер `NN` — две цифры с `01`, по порядку зависимостей (блокеры раньше); один тикет — один файл, общего файла тикетов нет.
- «Опубликовать в трекер» — создать файл в этих папках (папку — если нет). «Получить тикет» — прочитать файл по пути или номеру. «Закрыть» — `resolved` (п. 4). «Назначить на себя» — `claimed`.

## 2. Тикет карты

```
# NN: <заголовок>

Type: grilling
Status: claimed
Blocked by: 02, 05

## Question

<вопрос — решение или исследование, на одну сессию>
```

- `Type:` — `research` | `prototype` | `grilling` | `task` (типы — как в `wayfinder`). По нему выбирают навык: `research` → `research`, `prototype` → `prototype`, `grilling` → `grilling` и `domain-modeling`, `task` — сделать или дать пользователю список действий. Навыки, которые модель зовёт сама (`grilling`, `domain-modeling`, `code-review`, `tdd`, `research`, `prototype`, `diagnosing-bugs`), — инструментом Skill с префиксом `mattpocock-skills:`; остальные — файлом по `matt-skill.js`.
- Нет строки `Status:` — тикет открыт. Меток Мэтта (`ready-for-agent`, `needs-*`, `wontfix`) у тикетов карты нет; `claimed`, `ready-for-human`, `resolved` — статусы kit.
- `Blocked by:` — номерами через запятую; блокеров нет — строки нет.
- Карта `map.md` — разделы как у `wayfinder`: `## Destination`, `## Notes`, `## Decisions so far`, `## Not yet specified`, `## Out of scope`. Открытые тикеты в карте не перечисляются: их находят по папке `issues/`.

## 3. Тикет реализации

По шаблону `to-tickets`: `# NN: <заголовок>`, `**What to build:**`, `**Blocked by:** 01, 03` (номерами; блокеров нет — `None (can start immediately)`), `**Status:** ready-for-agent`, критерии `- [ ]`. Статус меняй в той же форме: `**Status:** claimed`, `**Status:** ready-for-human`, `**Status:** resolved`.

## 4. Статусы

| Статус | Кто ставит | Значит |
|---|---|---|
| нет (карта) / `ready-for-agent` (реализация) | общая сессия (карта) или исполнитель нарезки | открыт |
| `Status: claimed` | исполнитель — первым делом, до работы | взят |
| `Status: ready-for-human` | исполнитель | ждёт общую сессию: вопрос или «готово» |
| `Status: resolved` | общая сессия — после «Коммитить» (в порядке «Claude по SSH» — после «Залить на сервер» и проверки на сервере; без пользователя — после ревью), до коммита | закрыт |

- `ready-for-human` в kit значит «ждёт общую сессию», а не «делает человек», как у Мэтта. Работу, которую может сделать только пользователь, исполнитель пишет вопросом.
- Метки `triage` (`needs-triage`, `needs-info`, `wontfix`) — только у тикетов реализации, строкой `**Status:**`: `needs-*` — не во фронте (ждут общую сессию), `wontfix` — закрыт, как `resolved`.
- **Фронт** — открытые, незаблокированные (все из `Blocked by` — `resolved` или `wontfix`), не `claimed` и не `ready-for-human`, не `needs-*`; первый по номеру. Считает общая сессия.
- **Вопрос или готово** при `ready-for-human`:
  - вопрос — последняя запись в `## Comments` — `**Вопрос …**` без ответа, сводки «Готово:» нет;
  - готово — в тикете сводка «Готово:» (п. 5);
  - `ready-for-human` без вопроса и без «Готово:» — спроси пользователя, что с тикетом.

## 5. Что пишет исполнитель — только свой тикет (кроме нарезки)

- Взять: `Status: claimed` и сохранить — до начала работы.
- Ответ (тикет карты): под `## Answer` — решение полностью (что выбрано, почему, отвергнутое); подробности, ADR, прототип — ссылками.
- Вопрос: в конец файла под `## Comments` — `**Вопрос (ГГГГ-ММ-ДД):** …` с вариантами, `Status: ready-for-human`, и остановиться.
- Готово: в конец тикета сводка
  ```
  Готово: <что сделано, коротко>
  Проверки: <какие и итог>
  Файлы: <пути от корня проекта, через запятую>
  ```
  и `Status: ready-for-human`.
- Новые тикеты, правку и удаление других тикетов и карты не делает: перечисляет в отчёте (вопрос, `Type:`, блокеры; «вне границ» — с причиной).
- Исключение — исполнитель нарезки (`to-tickets`): его работа и есть новые тикеты — публикует их в `<docs>/work/<тема>-build/issues/` (п. 3) и пишет `<docs>/work/<тема>-build/README.md` с правилами тикетов; карту и тикеты карты не трогает.

## 6. Что пишет общая сессия

- До просмотра в `/kit:step-done` (раздел 4 — пользователь видит и это), в путях коммита: указатель в `## Decisions so far` карты — `- [<заголовок тикета>](issues/NN-<slug>.md): <суть ответа одной строкой>` (решение — только в тикете, в карте — указатель); новые тикеты из предложений отчёта — следующими свободными номерами, с `Blocked by`; то, что прояснилось, — из `## Not yet specified` в тикеты; вне границ — тикет `Status: resolved` и строка в `## Out of scope` с причиной.
- После «Коммитить» (в порядке «Claude по SSH» вопроса «Коммитить» нет — после «Залить на сервер» и проверки на сервере; без пользователя — после ревью), до коммита, в те же пути коммита: только `Status: resolved` принятого тикета.
- Коммиты подготовки: `map.md` и не взятые тикеты карты — в коммите первого принятого тикета, взятые — каждый в своём.
- Спек и нарезка (тикета нет): файлы коммита — по `git status --porcelain -uall` папок темы (без `-uall` новая папка — одной строкой), `<docs>/GLOSSARY.md`, `<docs>/adr/`; файлы идущих тикетов (если есть) не бери.
- Ответ пользователя на вопрос: в `## Comments` — `**Ответ (ГГГГ-ММ-ДД):** …`, статус — снова открыт (у карты строку `Status:` убрать, у реализации — `**Status:** ready-for-agent`): тикет возвращается во фронт.
- Номера новых ADR для параллельных тикетов — в задании исполнителю диапазоном «<NNNN>–<MMMM>», у каждого свой, без пересечений.
