## Решения обсуждения (2026-10-05)

- Чек-лист задач — в начале плана, строка на задачу = шаг kit (`- [ ] N.M — …`); при закрытии шага docs-keeper ставит `[x]`; чекбоксов внутри задач нет — подробные шаги обычным списком.
- Журнал — полное разделение на файлы (отвергнуто: только закрытые этапы в архив; этапы и исправленные баги в архив).
- Порядок — один этап: планы → журнал → обзор → выпуск.

## Раскладка журнала

```
<папка документов>/
  progress.md          «Сейчас», «Этапы» (оглавление), «Документы», «Прод: не забыть», текущий этап
  journal/
    decisions.md       «Решения»
    bugs.md            «Баги на потом»
    reference.md       «Справочник», «Материалы заказчика»
    stages/
      stage-21.md      закрытый этап: заголовок, таблица шагов, строка «Сверка …»
```

- Параметр «Журнал» по-прежнему указывает на `progress.md`; части — в `journal/` рядом с ним. Хук SessionStart читает только «Сейчас» — не меняется.
- «Этапы» — `| Этап | Название | Файл |`; текущий этап — строкой со ссылкой «ниже», закрытые — ссылкой на `journal/stages/stage-NN.md`.
- Раскладка определяется по наличию `journal/`: нет — всё в `progress.md`, как до 2.13.0 (старые проекты работают без перевода).
- Переносит части скрипт, а не модель: текст переносится строка в строку, без пересказа.

## Общие ограничения

- Файлы — UTF-8 без BOM, LF; файлы целиком не переформатировать.
- Перед каждым коммитом: `npm test`, `claude plugin validate plugins/kit --strict`, `claude plugin validate . --strict`, `node tools/kit-denylist.js tree`.
- Простота и надёжность: без тестов на экзотику; поведение агентов — один запуск на копии журнала.
- До выпуска установлен 2.12.0: после перевода журнала (26.4) docs-keeper — с текстом из репозитория (запасной путь), иначе старый агент вернёт «Решения» в `progress.md`.
