# Спецификация — коммит шага скриптом `kit-commit.js` вместо агента git-keeper

> Разделы kit поверх дизайна `superpowers:brainstorming`. Выбранный подход и отвергнутые — в «Решения» журнала (DECISIONS).

## Задача

- Номер: без задачи — баг К54 (`journal/bugs.md`)
- Цель: сообщение коммита попадает в git ровно таким, каким его составил основной агент; коммит шага делает программа, а не модель.

**Откуда.** Агент `kit:git-keeper` (модель haiku) перепечатывает заголовок, тело и подпись внутрь команды `git commit -m '…'` и при этом «исправляет» слова: «спек» → «спец» (`5e91723`, шаг 27.1), окончания («частям» → «частях»); раньше терял обратные кавычки (К51). Запрет «символ в символ» в тексте агента не помогает — это свойство модели. Работа агента механическая: проверки `secret-scan.js`, `git add`, один коммит, отчёт; на любую неожиданность он и так обязан остановиться.

## Требования

- Т-1. Скрипт `plugins/kit/scripts/kit-commit.js` делает ровно один коммит переданных файлов; сообщение читает из stdin и передаёт в git без оболочки (`git commit -F -`), без перепечатки.
- Т-2. Порядок и запреты — те же, что у git-keeper 2.13.0: корень репозитория — текущая папка; пустые файлы или сообщение — ошибка; `secret-scan.js --paths` до `git add`; уже помеченные в индексе удаления повторно не добавляются, `git add` без путей не выполняется; `secret-scan.js --cached` после `git add`; при остановке индекс остаётся как есть (К53); никаких `reset`, `restore`, `rm --cached`, `amend`, `push`.
- Т-3. Коммит — только переданные пути (`git commit -F - -- <пути>`): чужие файлы в индексе в коммит не попадают и остаются в индексе.
- Т-4. Самопроверка после коммита: новый коммит ровно один (родитель нового `HEAD` — прежний `HEAD`, для первого коммита — родителя нет); сообщение коммита совпадает с поданным с точностью до обычной чистки git (пробелы в конце строк, пустые строки в конце); в коммите нет путей сверх переданных.
- Т-5. Коды: 0 — коммит сделан и проверен; 1 — остановила проверка путей или секретов, коммита нет; 2 — ошибка запуска, git или хука, коммита нет; 3 — коммит есть, самопроверка нашла расхождение. Вывод — по-русски: хеш, заголовок, файлы (последняя строка статистики), `git status --short`; при остановке — вывод `secret-scan.js` (значения замаскированы) и что осталось в индексе.
- Т-6. Работает первый коммит репозитория (шаг 0.1 `/kit:project-init`) и кириллические пути.
- Т-7. `/kit:step-done` (п. 4–5) и `/kit:project-init` (первый коммит) вызывают скрипт одной командой Bash; сообщение — heredoc с кавычками `<<'KIT_MSG'`, который ничего не подставляет.
- Т-8. Агент `agents/git-keeper.md` удалён; упоминания git-keeper в плагине, README, спеке `spec-claude-kit.md` и обзоре `work/overview/` заменены скриптом.
- Т-9. Выпуск 2.14.0.

## Критерии готовности

- Тесты `tests/kit-commit.test.js` на временных репозиториях: сообщение со словами «спек», `` `php -l` ``, `$arResult`, апострофом и `/` в начале строки — в коммите побайтно; чужой файл в индексе не попадает в коммит; запрещённый путь — код 1 и пустой индекс; секрет в содержимом — код 1, индекс как есть; уже помеченное удаление; пустые файлы или сообщение — код 2; первый коммит; кириллический путь.
- `npm test`, `claude plugin validate plugins/kit --strict`, `claude plugin validate . --strict` — без ошибок.
- Живая проверка: шаги 28.2–28.4 этого репозитория закрываются новым скриптом из репозитория; сообщение коммита совпадает с поданным.
- В плагине нет упоминаний git-keeper, кроме истории (журнал, архив планов).

## Предположения

- Инструмент Bash есть в каждой сессии Claude Code, в том числе на Windows (Git Bash) — git-keeper уже коммитил только из Bash.
- `git commit -- <пути>` работает и для первого коммита репозитория — проверяется тестом.
- Первый коммит `/kit:project-init` передаёт пути так, как их выводит `git status --porcelain` (неотслеживаемые папки — одной строкой `папка/`), поэтому длина командной строки Windows не превышается.

## Дизайн

**Вызов** — из корня проекта, одной командой Bash:

```
node "<KIT_ROOT>/scripts/kit-commit.js" -- <путь1> <путь2> … <<'KIT_MSG'
<ID>: <заголовок>

<тело — CHECK дословно>

Co-Authored-By: …
KIT_MSG
```

Пути — отдельными аргументами в кавычках. Heredoc с кавычками не подставляет `$`, обратные кавычки и `\`; терминатор `KIT_MSG` в тексте сообщения не встречается.

**Порядок** (`main(argv, stdin)`):

1. Аргументы: пути после `--`; пусто — код 2. Сообщение из stdin: убрать `\r`, пустое после чистки — код 2.
2. `git rev-parse --show-toplevel` совпадает с текущей папкой — иначе код 2. Прежний `HEAD` — `git rev-parse --verify -q HEAD` (нет — первый коммит).
3. `node secret-scan.js --paths -- <пути>` (рядом со скриптом): 1 — код 1 с выводом скрипта; 2 — код 2.
4. Уже помеченные удаления: `git -c core.quotepath=false diff --cached --name-only --diff-filter=D`; остальные пути — `git add -A -- <пути>`; не осталось — `git add` не выполняется. Ошибка — код 2.
5. `node secret-scan.js --cached -- <пути>`: 1 — код 1, вывод скрипта и `git diff --cached --name-only`; индекс не трогается.
6. `git commit -F - -- <пути>`, сообщение — во входной поток процесса git (`spawnSync`, без оболочки: нет кавычек и переписывания путей Git Bash). Ошибка (в том числе хук `commit-msg`) — код 2 с выводом git.
7. Самопроверка (Т-4): `git rev-list --parents -n 1 HEAD`, `git cat-file commit HEAD` (сообщение — после первой пустой строки), `git diff-tree --no-commit-id --name-only -r --root HEAD` против путей (путь-папка покрывает всё внутри). Расхождение — код 3 с описанием.
8. Отчёт: `git show --stat --format="%h %s" HEAD` (последняя строка статистики), `git status --short`.

Все команды git — с `-c core.quotepath=false`; пути нормализуются к `/`.

**Модули.** `kit-commit.js` экспортирует `main` и разбор аргументов для тестов; `secret-scan.js` вызывается отдельным процессом — как у агента, его код не меняется.
