# Сводка глубокого исследования перед выпуском kit 3.3.0 (2026-10-28)

Источники: три отчёта исследования (A — навыки Мэтта против kit, B — стыки kit, C — платформа Claude Code; рабочие материалы, в git не кладутся). Повторы сведены; в скобках — номера находок в отчётах.

## Что подтвердилось (проблем нет)

- Новые стражи не ломают ни одного сценария kit и aspro: 48 команд и 36 путей из навыков — без ложных отказов (B).
- `claude plugin disable superpowers… --scope project` при superpowers на уровне пользователя работает; `false` проекта перекрывает `true` пользователя (C).
- `.claude/settings.json` в kit-проектах вне git — предпосылка Т-2 верна; решение пользователя 2026-10-28 — так и оставить.
- Хуки соответствуют контракту PreToolUse; PreToolUse срабатывает и на `mcp__ccd_session__start_session` (C).
- Вывод `session-start.js` в худшем случае — 7 817 символов при пределе 10 000 (C).
- guard-matt — около 50 мс на вызов (почти целиком запуск node) (B).
- В навыках Мэтта 1.3.1 нет конструкций, которые работают только при настоящем вызове (`!`команда``, `$ARGUMENTS` и т. п.); хуков, агентов, MCP у плагина нет (A, C).
- Журнал с папками Мэтта: STAGE со скобками и путём, DOCS-папки, перенос обеих папок в archive/, NEXT с путём — работают (опыт B).

## Отложено по ходу исправлений (47.8б–47.8ж) — в 3.3.1

- Стражи: формы `git checkout -fb`, `command`/`sudo`/`env`/`xargs`/`bash -c`, `x=$(git commit)`; `GIT_WORK_TREE`/`GIT_DIR` перед командой; `git --help commit` и голая `{` в `stash push -m` — ложные отказы; `restore --source X --staged` при Always — лишний отказ; rebase через `pull -qr`, `-c pull.rebase=true`, настройки git — проходят, `pull --rebase=no` — ложный отказ; локальная ветка со слешем (`feature/x`, `claude/<имя>`) считается удалённой при merge; проект в подпапке репозитория — `git -C ..` считается чужой целью.
- При Always слияние удалённой ветки или `git pull` с конфликтом оставляют маркеры на диске (общий риск kit, не только Мэтт); README, обзор, `MATT_ALWAYS` и `REASON_REWRITE` перечисляют не все запреты стража; «переход на другой коммит» можно прочесть как запрет `pull --ff-only`; `remote-check.js` при разошедшейся ветке советует rebase «с согласия», а в проекте Мэтта при Always rebase запрещён.
- guard-matt: журнал в корне (`docsRel "."`) — пропускается всё; выражение «PhpStorm Always» продублировано в двух хуках.
- matt.js: несколько записей плагина — первая без приоритета local > project > user; `skills` в plugin.json — только массив; пустая версия даёт «стоит , …».
- Скрипты: регистр сегментов внутри корня; сбой удаления при откате journal-split (повтор `--migrate` снова даёт ложный код 0); «ничего не записал» в stage-close.md и project-init неточно при частичной записи; в ветке кода 3 kit-commit нет `git status --short`; тесты index.lock зависят от времени.
- /kit:matt: запас ядра — несколько байт (следующая правка — вынос в reference/); `tracker.md` — возврат тикета реализации в `ready-for-agent` не в таблице, ветка ssh.md «код 0, всё совпало»; ядро без оговорки SSH про `resolved` (есть в трекере).
- session-start: худший случай вывода — 8 990 символов при тесте ≤ 9 000 (предел платформы 10 000) — новые общие строки потребуют сжатия; `RULE_WORKTREE` в обычных проектах не выводится в worktree-сессии приложения (путь worktree — только в `cwd` входа).
