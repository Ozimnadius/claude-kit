## Задача

- Номер: без задачи — идея пользователя (2026-10-28): «надо подумать, как внедрить в нашу систему https://github.com/mattpocock/skills — или вилки делать, или ещё что-то».

**Откуда.**
- `mattpocock/skills` — 27 навыков, лицензия MIT. Плагин `mattpocock-skills` (1.3.1 на 2026-10-28) есть в официальном маркетплейсе `claude-plugins-official` и обновляется сам. Репозиторий меняется почти каждый день; новых навыков автор не принимает, подстройку под себя советует делать правилами в своём `CLAUDE.md` или вилкой.
- Главный процесс Мэтта: грилинг (вопросы до кода) с глоссарием и ADR → карта решений `wayfinder` → спек `to-spec` → тикеты `to-tickets` → реализация `implement` по тикету с `tdd` и `code-review`. 16 навыков запускаются только командой (`disable-model-invocation: true`): `ask-matt`, `grill-with-docs`, `grill-me`, `triage`, `improve-codebase-architecture`, `setup-matt-pocock-skills`, `to-spec`, `to-tickets`, `wayfinder`, `implement`, `implement-spec`, `retro`, `handoff`, `teach`, `to-questionnaire`, `wait-what`. Остальные 11 Claude может вызвать сам; пять из них — двойники superpowers: `tdd`, `diagnosing-bugs`, `code-review`, `grilling`, `writing-for-agents`.
- Опытный проект alpha (2026-10-24…25, вне kit): плагин поставлен только на проект (`claude plugin install mattpocock-skills@claude-plugins-official --scope project`), superpowers в нём выключен (`claude plugin disable superpowers@claude-plugins-official --scope project`). Карта из 29 тикетов-решений закрыта за один день → 22 ADR, глоссарий 16 КБ, спек 165 КБ → 55 тикетов реализации, к середине следующего дня принято 18. Как это было устроено:
  - одна общая сессия — координатор; на каждый тикет она запускала исполнителя со свежим контекстом и коротким заданием (путь к тикету, что прочитать, какие навыки, что не трогать) и получала от него короткий отчёт;
  - пока пользователь был рядом, исполнитель — подчинённая сессия приложения Claude (контекст fresh, без worktree), иногда по две сразу; пользователь отвечал на вопросы грилинга в ней;
  - когда пользователь сказал «работай автономно», общая сессия перешла на фоновых субагентов (запуск сессии требует разрешения пользователя, субагента — нет): тикеты шли подряд, между ними проверка расхода лимитов, тикет принимала сама общая сессия коммитом, вопросы к пользователю копились в тикетах до утра;
  - главные навыки Мэтта Claude вызвать не может, поэтому задание говорило: «пользователь введёт `/mattpocock-skills:…`; если нет — прочитай файл навыка из кэша плагина и следуй ему»;
  - русский язык дали общие правила пользователя, от совпадения имён со встроенными `/code-review` и `/research` — правило в `CLAUDE.md` звать навыки с префиксом `mattpocock-skills:`.
- В kit уже есть три способа подключать чужое: правила поверх установленного плагина (superpowers, решение 2026-10-05; в журнале багов нет случаев, чтобы он коммитил сам или писал не туда), скачивание скиллов скриптом в проект по вопросу `/kit:project-init` (`bitrix-skills.js`), свой плагин в маркетплейсе (`aspro`).
- Где Мэтт сталкивается с kit: (1) пишет в корень проекта `GLOSSARY.md`, `docs/adr/`, `.scratch/`, `docs/agents/` — на сайте это корень сайта, автозаливка увезёт их на сервер; (2) `implement` велит коммитить, `implement-spec` и `wayfinder` заводят ветки — в kit коммит только через `/kit:step-done`, при автозаливке без веток; (3) состояние работы в строках `Status:` тикетов и в карте, а у kit — в журнале; (4) вопросы грилинга Мэтт нарочно задаёт текстом — у пользователя правило «вопросы только через AskUserQuestion» (автор сам советует решать это строкой в своих правилах).

**Решения пользователя (2026-10-28).**

Отвергнуто: Claude предлагает по ходу работы; вопрос в начале каждого этапа.
- В проекте с системой Мэтта superpowers выключается, как в alpha: работают только навыки Мэтта. Отвергнуто: оставить оба и разводить двойников правилами kit.
- Файлы Мэтта — обычные документы kit: лежат в папке документов и уходят на сервер или нет по общему правилу «Документы на сервере».

Предложил Claude; на вопрос пользователя «будет ли адаптер нормально работать» — ответ «да, если подстраховать хуками три места: коммиты, ветки, файлы в корне». Отвергнуто: вилка (автор правит навыки ежедневно, перевод превращает каждое слияние в ручную работу); свои навыки kit по мотивам Мэтта (нужен весь процесс, а не одна-две идеи); не смешивать — Мэтт только в проектах без kit.

## Требования

`<docs>` — папка документов проекта (обычно `.claude/docs`); `<тема>` — короткое имя большой работы; **проект Мэтта** — kit-проект с ответом «да» на вопрос Т-1.

- Т-1. **Настройка.** `/kit:project-init` спрашивает «Вести проект по системе Мэтта Покока?» с пояснением в одну-две строки (для больших проектов: грилинг, карта решений, спек, тикеты, каждый тикет — свежая сессия; superpowers в проекте выключается). Ответ — параметром в «Параметры для агентов» (рабочее имя `- Система Мэтта: да|нет`, строка и в шаблоне `templates/CLAUDE.md`). «Да» — как в alpha: `claude plugin install mattpocock-skills@claude-plugins-official --scope project` и `claude plugin disable superpowers@claude-plugins-official --scope project`, затем перезапуск сессии. «Нет» — ничего не ставится, всё как сейчас. Существующие kit-проекты получают вопрос, когда догоняют настройку через `/kit:project-init` (отметка «Версия kit»). По ходу работы Claude систему Мэтта не предлагает.
- Т-2. **Смена ответа и другой компьютер.** Повторный `/kit:project-init` может сменить ответ: «нет» после «да» — плагин Мэтта в проекте выключается, superpowers включается обратно; глоссарий, ADR и папки тем остаются. Включение плагинов на проект записано в `.claude/settings.json`, а он не в git, поэтому при «да», когда плагин не стоит на проект (другой компьютер, не скачался без сети), `session-start.js` напоминает запустить `/kit:project-init`.
- Т-3. **Навык kit** для проекта Мэтта (рабочее имя `/kit:matt`; Claude вызывает его сам, когда начинается большая работа): протокол общей сессии (Т-5…Т-9), шаблон задания исполнителю, приёмка, режим без пользователя. По-русски. В контекст старта сессии проекта Мэтта — только указатель на навык, места файлов (Т-4) и строка про идущую большую работу (Т-11); строка правил superpowers в проекте Мэтта не выводится.
- Т-4. **Места файлов** в проекте Мэтта (отдельные навыки по команде тоже пишут глоссарий и ADR, поэтому правило действует всегда, а не только в большой работе):
  - карта, её тикеты-решения и спек — `<docs>/work/<тема>/`: `map.md`, `issues/NN-<slug>.md`, `spec.md`; без карты там только `spec.md`;
  - тикеты реализации — отдельной папкой `<docs>/work/<тема>-build/`: `issues/NN-<slug>.md` и правила тикетов `README.md` (как в alpha: `wayfinder` и `to-tickets` нумеруют тикеты с `01`, в одной папке номера столкнулись бы);
  - обе папки переезжают в `<docs>/archive/` вместе, когда закрыт этап реализации: тикеты реализации ссылаются на спек и тикеты карты;
  - глоссарий — `<docs>/GLOSSARY.md`, ADR — `<docs>/adr/NNNN-<slug>.md`; остаются навсегда;
  - исследования (`research`), опросники (`to-questionnaire`) и прочие документы навыков — в `<docs>/work/`; одноразовые прототипы (`prototype`) — HTML в `<docs>/work/<тема>/`, варианты экранов на самом сайте — только там, где правки не уходят на прод сами;
  - в реестр «Документы» журнала — строкой DOCS в `/kit:step-done`; на сервер — по «Документы на сервере»;
  - спек и план kit (`spec-*.md` по шаблону kit, `plan-*.md` с чек-листом) в проекте Мэтта не пишутся — их заменяют спек и тикеты Мэтта;
  - настройку, которую у Мэтта пишет `setup-matt-pocock-skills` (трекер — локальные файлы, глоссарий и ADR), даёт текст kit, а не файлы `docs/agents/` в проекте.
- Т-5. **Общая сессия.** Большую работу (не влезет в одну-две сессии) Claude ведёт через общую сессию; маршрут — карта `wayfinder`, или грилинг → спек → тикеты, или сразу сделать — выбирает, как `ask-matt`, и предлагает пользователю через AskUserQuestion. Мелкая задача — без карты и тикетов: сделать и закрыть `/kit:step-done`. Общая сессия — координатор: держит карту и очередь тикетов (фронт: открытые, незаблокированные, не взятые), запускает исполнителя на каждый тикет, получает отчёт, принимает тикет (Т-8). Тикеты сама не решает; её контекст растёт только на отчёты.
- Т-6. **Исполнитель** делает ровно один тикет со свежим контекстом:
  - тикет с пользователем (грилинг, вопросы) — подчинённая сессия приложения Claude (контекст fresh, без worktree); таких может идти несколько сразу;
  - тикет без пользователя — фоновый субагент; тикеты реализации — по одному подряд;
  - задание — по шаблону навыка kit: путь к тикету; что прочитать (правила тикетов, разделы спека по ссылкам тикета, ADR, глоссарий); какой навык Мэтта и путь к его файлу (Т-7); запреты — не коммитить, без веток и worktree, документы только в `<docs>/`, папку `.idea` не трогать; вопросы — через AskUserQuestion, по-русски; формат отчёта (что сделано, какие файлы, какие проверки прошли, вопросы к пользователю).
- Т-7. **Запуск навыков Мэтта.** Навыки только по команде Claude вызвать не может: kit даёт путь к файлу навыка в установленной версии плагина (по `~/.claude/plugins/installed_plugins.json`: `installPath` + `skills/<раздел>/<имя>/SKILL.md`), исполнитель читает файл и следует ему; пользователь может и сам ввести `/mattpocock-skills:<имя>`. Путь не ломается при обновлении плагина. Навыки Мэтта — всегда с префиксом `mattpocock-skills:`.
- Т-8. **Приёмка.** Тикет = шаг kit `<этап>.<номер тикета>`; исполнитель не коммитит. Общая сессия закрывает тикет через `/kit:step-done`: просмотр изменений, ответ «Коммитить», один коммит только с файлами тикета (`kit-commit.js` с путями); в тикете — `Status: resolved`. Исправления после замечаний — шагами с буквой (`N.Mа`). В режиме «Claude по SSH» — как обычно: заливка и проверка на сервере до коммита.
- Т-9. **Без пользователя** — только когда пользователь сам разрешил работать без него:
  - тикет закрывается скриптами kit после проверок проекта и независимого ревью субагентом (`mattpocock-skills:code-review`), без вопроса «Коммитить»; в тикете и журнале — пометка «принят без просмотра»;
  - вопрос к пользователю — в `## Comments` тикета, тикет — `ready-for-human`, работа идёт к следующему незаблокированному;
  - между тикетами — проверка расхода лимитов; остановка до лимита и к сроку, который назвал пользователь;
  - когда пользователь вернулся — общая сессия показывает принятые без него тикеты по одному (сводка и изменения коммита), замечания — исправлениями по Т-8, вопросы из `## Comments` — через AskUserQuestion;
  - не включается при «Выкладка: PhpStorm Always» с окружением «прод»; при «Claude по SSH» тикеты без пользователя на сервер не заливаются — заливка и проверка на сервере при разборе.
- Т-10. **Не используются** в проекте Мэтта: `implement-spec` (интеграционная ветка и параллельные исполнители в одной папке) и `setup-matt-pocock-skills` (его настройку даёт kit, Т-4).
- Т-11. **Журнал.** Идущая большая работа видна в «Сейчас» (этап, папки `<docs>/work/<тема>/` и `<тема>-build/`, следующие тикеты), чтобы новая сессия и общая после сжатия контекста знали, где карта и тикеты. Решения: полный текст — в ответе тикета и в ADR; в `decisions.md` — строка со ссылкой, без пересказа. Входящие ответы (`decision-inbox.js`) из грилинга в подчинённых сессиях не теряются и не задваиваются.
- Т-12. **Подстраховка хуками** в проектах Мэтта, сообщения — по-русски, с подсказкой, как правильно:
  - а) `git commit` в обход `kit-commit.js` не проходит;
  - б) при «Выкладка: PhpStorm Always» не проходят создание веток и worktree (git, субагент с отдельной копией, подчинённая сессия с worktree);
  - в) не проходит запись в корень проекта `GLOSSARY.md`, `GLOSSARY-MAP.md`, `CONTEXT.md`, `CONTEXT-MAP.md`, `docs/adr/`, `docs/agents/`, `.scratch/`.
- Т-13. **Версия.** kit знает версию плагина Мэтта, на которой проверены его правила. Пока идёт большая работа и установлена другая версия — напоминание Claude сверить правила (пользователю на каждом старте не показывается).
- Т-14. **Проверки:** тесты новых хуков, правил старта и вопроса `/kit:project-init` (`node --test`), `npm test`, `claude plugin validate plugins/kit --strict`, `claude plugin validate . --strict`, `node tools/kit-denylist.js tree`.
- Т-15. **Выпуск** kit 3.3.0 (вопрос и параметр настройки, навык, хуки): версии в `plugin.json` и `marketplace.json`; README — раздел о системе Мэтта (что это, вопрос при настройке, что ставится и выключается, общая сессия и исполнители, режим без пользователя); обзор `work/overview/` — пересобрать (выпуск добавляет навык, хуки и режим).
- Т-16. **Обезличенно:** в файлах и коммитах — без имён проектов пользователя и клиентов (опытный проект — alpha).

## Критерии готовности

Живая проверка — на kit-проекте, который выберет пользователь:
- `/kit:project-init` задаёт вопрос; «да» → параметр записан, плагин Мэтта стоит на проект, superpowers в проекте выключен, после перезапуска навыки Мэтта видны с префиксом `mattpocock-skills:`, навыков superpowers нет; «нет» → ничего не меняется;
- в проекте Мэтта мелкая задача идёт без карты и тикетов и закрывается `/kit:step-done`; большая → Claude предлагает маршрут, сессия становится общей; карта или спек и тикеты — в `<docs>/work/<тема>/`, глоссарий и ADR — в `<docs>/`; в корне проекта ничего не появилось;
- тикет с пользователем идёт в подчинённой сессии, тикет без пользователя — у субагента; каждый принят через `/kit:step-done` одним коммитом только с файлами тикета, `Status: resolved`, «Сейчас» журнала показывает следующий тикет;
- режим без пользователя: два-три тикета подряд субагентами, коммиты с пометкой «принят без просмотра», разбор после возвращения; при «PhpStorm Always» на прод режим не включается;
- смена ответа на «нет» возвращает superpowers; при «да» без плагина на проекте — напоминание о `/kit:project-init`;
- хуки Т-12 останавливают попытку `git commit`, ветку при автозаливке и `GLOSSARY.md` в корне — с подсказкой;
- проверки Т-14 зелёные.

## Дизайн

**Как это выглядит для пользователя.**
1. `/kit:project-init` в новом проекте (или когда проект догоняет настройку) спрашивает: «Вести проект по системе Мэтта Покока?». «Нет» — всё как сейчас.
2. «Да» — kit ставит плагин Мэтта на этот проект и выключает в нём superpowers; после перезапуска сессии работают навыки Мэтта.
3. Мелкая задача — Claude делает её и закрывает `/kit:step-done`, без карты и тикетов.
