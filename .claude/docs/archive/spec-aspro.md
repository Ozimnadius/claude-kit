# Спецификация — плагин aspro: сверка доработок с обновлением решений Аспро (этап 37)

## Задача

- Номер: без задачи — решение пользователя (2026-10-18): скил и инструмент сверки Аспро выпускать отдельным плагином `aspro` в
  маркетплейсе claude-kit, а не внутри `kit` и не отдельным репозиторием.
- Цель: команда ставит плагин `aspro@claude-kit` и в папке сайта на «Аспро» (Оптимус, Корпоративный сайт 3.0 и др.) говорит
  Claude «внедри сверку Аспро» / «сверь обновление Аспро». Доработки сайта — обычная правка файлов шаблона (копия
  `local/templates/<шаблон>` или сам `bitrix/templates/<шаблон>`), после обновления решения в админке сайт сам сливает очевидное,
  конфликты разбирает Claude по скилу.

**Откуда.** Инструмент и скил сделаны и проверены в приватной лаборатории пользователя: два настоящих обновления «Аспро: Оптимус»
1.7.20 → 1.7.21 из админки (режимы «копия» и «на месте») — итог совпал с проверенной сверкой; конфликты разобрал агент, знавший
только скил; 11 наборов тестов (580+ проверок), движок слияния совпадает с `git merge-file`. В лаборатории остаются стенд, тесты на
настоящих пакетах Аспро (платный код вендора) и демо; в плагин — только инструмент без тестов, скил и документы.

## Требования

- Т-1. Плагин `plugins/aspro/` с `.claude-plugin/plugin.json` (`name: aspro`, `version: 1.0.0`, описание по-русски, автор,
  homepage/repository, лицензия MIT, ключевые слова) и записью в `.claude-plugin/marketplace.json`.
- Т-2. Скил `plugins/aspro/skills/aspro-merge/SKILL.md` — вызывается как `aspro:aspro-merge`; рядом — `tool/` (инструмент: консоль
  `merge.php`, `lib/`, `README.md`, `config.example.php`, `.htaccess`, `integration/aspro_merge.php` — файл подключения для
  `local/php_interface/include/`) и `docs/` (`GUIDE.md` — инструкция для команды, `DESIGN.md` — устройство).
- Т-3. Содержимое `skills/aspro-merge/` приходит из лаборатории её скриптом выпуска, без ручных правок в claude-kit; правки — в
  лаборатории и новым выпуском.
- Т-4. Лицензии: плагин — MIT; `tool/lib/xmerge.php` — порт xdiff из git (LibXDiff), LGPL-2.1-or-later, с дословными уведомлениями
  исходников; полный текст LGPL 2.1 — `tool/lib/LICENSE-LGPL-2.1.txt` (официальный текст с gnu.org), пояснение — `tool/lib/LICENSE-xmerge.md`.
- Т-5. Обезличенно: в плагине нет имён сайтов, проектов и клиентов пользователя, доменов кроме `*.example.com`, личных путей,
  e-mail (кроме автора LibXDiff в дословном уведомлении), ключей.
- Т-6. Тест `tests/aspro-plugin.test.js`: версии `plugin.json`, `marketplace.json` и инструмента (`AsproMerge\Tool::VERSION`,
  `AsproMergeSite::VERSION`) совпадают; на месте обязательные файлы (Т-2, Т-4); в поставке только `.php`, `.md`, `.json`,
  `.htaccess`, `.txt` (лицензия); `SKILL.md` с корректным frontmatter (`name`, `description`). PHP в тестах не нужен.
- Т-7. `claude plugin validate plugins/aspro --strict`, `claude plugin validate plugins/kit --strict`,
  `claude plugin validate . --strict` и `npm test` проходят.
- Т-8. README claude-kit: маркетплейс теперь с двумя плагинами; раздел «Плагин aspro» — что это, установка
  (`claude plugin install aspro@claude-kit`), что нужно на сайте (PHP CLI 8.1+), ссылки на `GUIDE.md` и `SKILL.md`; описание
  маркетплейса в `marketplace.json` — с обоими плагинами.
- Т-9. Плагин `kit` не меняется (версия 3.0.0); обзор `work/overview/` описывает `kit` и не пересобирается.

## Критерии готовности

- `claude plugin install aspro@claude-kit` после обновления маркетплейса ставит плагин, скил `aspro:aspro-merge` виден.
- Проверки Т-7 зелёные, `node tools/kit-denylist.js tree` — чисто.
- Скрипт выпуска лаборатории в режиме записи проходит (полный текст LGPL на месте) и повторный выпуск ничего не меняет.

## Вне этапа

- Связка с `kit` (режим «Claude по SSH», файл-канал `kit-exec.php` для сайтов без SSH) — позже, отдельным этапом.
- Автотесты инструмента (нужны настоящие пакеты Аспро) — остаются в лаборатории.
